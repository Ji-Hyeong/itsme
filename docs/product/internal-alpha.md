# 내부 알파 제품 범위와 인수 기준

- 문서 상태: 구현 기준
- 대상: 초대된 내부 테스터
- 핵심 여정: `로그인 → 질문 → 영구 저장 → 수정과 버전 확인 → 공개 선택 → 공개 URL 확인 → 공개 해제 또는 삭제`

## 문제

현재 프로토타입은 자기 기록과 공개 경험의 흐름을 검증했지만, 앱을 다시 시작하면 기록이
초기화되고 실제 사용자 경계가 없다. 따라서 다음 제품 가설을 검증할 수 없다.

- 사용자는 자신의 기록이 안전하게 보존된다고 믿을 때 며칠에 걸쳐 다시 돌아와 회고한다.
- 사용자는 비공개가 기본이고 실제 공개 결과를 먼저 볼 수 있을 때 일부 기록을 안심하고 공유한다.
- 과거 버전이 보존되면 사용자는 변화를 우열이 아닌 당시의 맥락으로 돌아볼 수 있다.

내부 알파의 문제는 기능 수를 늘리는 것이 아니라, 한 명의 사용자가 자신의 기록을 소유하고
보존하며 선택한 일부만 익명 방문자에게 노출하는 경계를 실제 서버 환경에서 검증하는 것이다.

### 확인된 사실

- 프로토타입에는 질문, 현재의 나, 수정, 버전, 변화, 공개 선택과 공개 미리보기 흐름이 있다.
- 제품 원칙은 새 기록의 `private` 기본값, 항목별 공개와 과거 버전 보존을 요구한다.
- 공개 응답은 소유자 응답과 분리하고 서버가 공개 범위를 최종 강제해야 한다.

### 검증할 가설

- 영구 저장된 기록을 다시 확인하는 경험이 자기이해와 회고 행동을 늘린다.
- 공개 전 미리보기와 명시적 확인이 공개 범위에 대한 확신을 높인다.
- 수정 이력을 당시의 맥락과 함께 보여주면 변화가 평가받는다는 느낌을 줄인다.

### 미확정 정책

- 정식 출시의 가입 방식, 본인 확인 수준, 비밀번호 재설정과 다중 인증
- 정식 출시의 휴면 계정, 법정 보존 의무, 백업 삭제 기한과 계정 삭제 유예 기간
- 공개 slug 변경, 만료 링크와 특정 대상에게만 공개하는 제한 공개
- 기록 내보내기의 형식과 제공 시점

이 항목들은 내부 알파의 임시 운영 정책을 정식 출시 정책으로 자동 승격하지 않고 별도로
검토한다.

## 사용자 가치

- 사용자는 로그인한 뒤 자신이 남긴 기록만 보고 바꿀 수 있으며, 앱이나 서버를 다시 시작해도
  기록이 유지된다는 확신을 얻는다.
- 사용자는 모든 질문을 건너뛸 수 있고, 짧은 답 하나만 남겨도 현재의 자신을 시작할 수 있다.
- 사용자는 기록을 고쳐도 이전 표현과 당시 맥락을 잃지 않고 시간에 따른 변화를 돌아본다.
- 사용자는 저장과 공개를 별도로 수행하고 실제 방문자 화면을 확인한 뒤 공유 여부를 결정한다.
- 사용자는 공개 해제와 삭제의 차이 및 결과를 알고 선택하며, 삭제한 원문이 다시 노출되지
  않는다는 확신을 얻는다.

## 범위

### Must

- 운영자가 미리 발급한 내부 테스터 계정으로 로그인하고 로그아웃한다.
- 선택형과 짧은 서술형 질문에 답하거나 모두 건너뛴다.
- 답변을 `private` 기록으로 영구 저장하고 재로그인, 앱 재실행과 서버 재시작 후 다시 조회한다.
- `현재의 나`에서 카테고리별 현재 기록과 비어 있는 상태를 확인한다.
- 기록의 현재 값, 선택적 근거, 변화 이유와 다음 시도를 수정한다.
- 수정 직전의 값과 맥락, 기록 시점을 변경 불가능한 과거 버전으로 확인한다.
- 항목별 공개 범위를 선택하고, 실제 공개 응답으로 렌더링한 미리보기에서 확인한 뒤 공개한다.
- 로그인하지 않은 방문자가 안정적인 공개 URL에서 현재 공개 항목만 조회한다.
- 항목을 공개 해제하거나 개별 삭제하고 개인 화면과 공개 URL에 일관되게 반영한다.
- 로딩, 빈 상태, 인증 만료, 권한 없음, 검증 오류, 충돌과 서버 오류에서 입력을 잃지 않고
  재시도하거나 로그인으로 돌아간다.

### Later

- 사용자의 자가 가입, 이메일 인증, 비밀번호 재설정과 다중 인증
- 계정 삭제 셀프서비스, 데이터 내보내기와 정식 백업 삭제 자동화
- 공개 slug 변경, 링크 만료와 특정 사람만 보는 제한 공개
- 오프라인 작성, 여러 기기의 실시간 동기화와 상세 충돌 병합
- 매주 질문, 개인 회고 리포트와 외부 콘텐츠 가져오기
- 친구와 점수 없이 공통 관심사를 확인하거나 답변을 요청하는 경험

### Won't

- 좋아요, 팔로워, 조회수, 인기 순위, 프로필 완성도와 경쟁형 연속 기록
- 사용자 간 궁합률, 강점 점수, 성장·퇴보 판정과 타인 비교 피드
- AI 성격·정신건강·능력 진단, 자유 서술 자동 해석과 입력하지 않은 정보 추론
- 공개 댓글, 다이렉트 메시지, 사용자 검색과 추천
- 운영자용 자유 서술 원문 검색, 원문 기반 분석 이벤트와 광고·추천 활용
- 내부 알파를 공개 서비스처럼 홍보하거나 검색 엔진에 색인하는 일

## 흐름

### 1. 로그인

1. 초대받은 테스터가 발급된 계정 정보로 로그인한다.
2. 실패 시 계정 존재 여부를 구분하지 않는 오류를 보고 입력을 수정하거나 다시 시도한다.
3. 성공하면 자신의 `현재의 나`로 이동한다. 저장된 기록이 없으면 비어 있는 상태와 질문
   시작 선택지를 함께 본다.

### 2. 질문과 영구 저장

1. 사용자는 질문마다 답하거나 건너뛴다. 건너뛰기는 기록을 만들지 않는다.
2. 저장 전에 새 기록이 `나만 보기`임을 확인한다.
3. 저장 중 중복 제출을 막는다. 실패하면 작성 중인 답을 유지하고 재시도할 수 있다.
4. 성공한 기록은 즉시 `현재의 나`에 반영되고 새 세션과 서버 재시작 후에도 동일하게 보인다.

### 3. 수정과 버전

1. 소유자는 현재 기록을 열어 값과 선택적 맥락을 수정한다.
2. 저장 시 기존 현재 값과 맥락, 기록 시점을 과거 버전으로 보존하고 새 버전을 현재로 둔다.
3. 공개 중이던 항목을 수정하면 안전을 위해 자동으로 `private`가 되며, 새 내용은 다시
   미리보고 공개하기 전까지 공개 URL에서 보이지 않는다.
4. 다른 세션이 먼저 같은 기록을 바꿨다면 서버는 오래된 수정을 거절한다. 사용자는 자신의
   작성 내용을 잃지 않은 채 최신 기록을 확인하고 다시 저장할 수 있다.

### 4. 공개 선택과 미리보기

1. 소유자는 공개 설정에서 항목별로 공개 후보를 명시적으로 선택한다.
2. 미리보기는 방문자와 동일한 공개 응답 모델과 렌더러를 사용한다.
3. 미리보기에는 현재 값과 공개용 표시 정보만 있고, 과거 버전, 근거, 변화 이유, 다음 시도와
   비공개 항목은 없다.
4. 사용자가 최종 확인해야 공개 범위가 바뀐다. 저장 성공만으로 공개되지 않는다.

### 5. 공개 URL

1. 방문자는 로그인하지 않고 공개 URL에 접근한다.
2. 존재하는 공개 프로필에는 그 시점에 `public`인 현재 항목만 보인다.
3. 공개 항목이 없으면 실패나 미완성 점수 대신 `아직 공개한 항목이 없어요` 상태를 본다.
4. 존재하지 않거나 사용할 수 없는 slug는 개인 정보 없이 찾을 수 없음 상태를 반환한다.

### 6. 공개 해제와 삭제

1. 공개 해제는 개인 기록과 과거 버전을 유지하면서 방문자 응답에서 현재 항목만 제거한다.
2. 삭제는 공개 해제와 다른 영구 행동임을 설명하고 해당 항목명을 확인한 뒤 실행한다.
3. 삭제가 성공하면 현재 기록, 모든 과거 버전과 해당 원문을 포함한 파생 공개 데이터가
   함께 제거된다. 삭제한 항목을 복구하는 기능은 내부 알파에 없다.
4. 실패하면 삭제된 것처럼 숨기지 않고 기존 상태와 재시도 방법을 보여준다.

## 정책

### 권한 행렬

| 자원 또는 행동 | 비로그인 방문자 | 로그인한 다른 사용자 | 소유자 | 내부 운영자 |
| --- | --- | --- | --- | --- |
| 로그인·로그아웃 | 로그인만 가능 | 로그아웃 가능 | 로그아웃 가능 | 계정 발급·접근 회수 |
| 소유자 프로필과 현재 기록 조회 | 불가 | 불가 | 가능 | 기본 불가 |
| 질문 답변과 기록 생성 | 불가 | 불가 | 가능 | 불가 |
| 기록 수정·과거 버전 조회 | 불가 | 불가 | 가능 | 불가 |
| 공개 후보 선택·미리보기·공개 해제 | 불가 | 불가 | 가능 | 불가 |
| 공개 URL 조회 | 공개 항목만 가능 | 공개 항목만 가능 | 공개 항목만 가능 | 공개 항목만 가능 |
| 개별 기록 삭제 | 불가 | 불가 | 가능 | 기본 불가 |
| 테스트 계정 전체 삭제 요청 처리 | 불가 | 불가 | 요청 가능 | 본인 확인 후 가능 |

- 소유자 API는 인증된 세션의 사용자 식별자를 기준으로 동작하며 요청자가 임의의 사용자 ID를
  지정해 다른 사람의 데이터를 조회하지 못한다.
- 다른 사용자의 기록 ID에 접근한 요청은 존재 여부를 유추하지 못하도록 `찾을 수 없음`으로
  처리한다. 인증되지 않은 소유자 요청은 `인증 필요`로 구분한다.
- 내부 운영자는 장애 대응을 이유로 자유 서술 원문을 임의 조회하지 않는다. 원문 접근이 필요한
  예외 절차와 감사 기록은 정식 운영 설계 전까지 제공하지 않으므로 내부 알파에서도 기본 차단한다.

### 공개 정책

- 새 기록과 수정된 기록의 기본 공개 범위는 항상 `private`다.
- 공개 전환은 항목별 선택, 방문자와 동일한 미리보기, 최종 확인의 세 단계를 거친다.
- 공개 응답에는 표시 이름, 공개 slug, 항목 카테고리, 현재 값과 필요한 표시 순서만 포함한다.
- 공개 응답에는 계정 이메일, 내부 식별자, 과거 버전, 작성 근거, 변화 이유, 다음 시도와 비공개
  항목을 직렬화하지 않는다.
- 내부 알파의 공개 응답은 공유 캐시와 검색 엔진 색인을 허용하지 않는다. 공개 해제나 삭제가
  성공한 뒤 새 서버 응답에는 즉시 반영한다.
- 이미 화면을 보거나 별도로 복사·촬영한 상대의 사본까지 회수할 수 없다는 한계를 공개 직전에
  안내한다.

### 삭제 정책

- `숨김`, `공개 해제`, `개별 기록 삭제`, `계정 전체 삭제`를 서로 다른 행동과 문구로 다룬다.
- 개별 기록 삭제는 현재 값, 모든 버전, 맥락, 공개 투영과 검색·캐시 사본을 한 작업 단위로
  제거한다. 통계가 필요하면 원문과 연결할 수 없는 집계 수치만 남긴다.
- 개별 삭제 성공 후 소유자 조회와 공개 조회에서 해당 항목이 없어야 하며, 같은 삭제 요청을
  다시 보내도 다른 사용자의 데이터에 영향을 주지 않는다.
- 내부 알파는 삭제 데이터의 앱 내 복구를 제공하지 않는다. 백업 복제본은 운영 복구 목적 외에
  조회하거나 다시 서비스하지 않으며, 내부 알파 종료 후 최종 파기 시점을 기록한다.
- 계정 전체 삭제 셀프서비스는 Later다. 내부 테스터는 운영자에게 삭제를 요청할 수 있고,
  운영자는 본인 확인 후 계정, 기록, 버전, 세션과 공개 프로필을 일괄 제거하고 완료를 통지한다.
- 정식 출시 전에는 법정 보존 대상, 삭제 유예, 백업에서의 최대 삭제 기한을 별도 승인해야 한다.

### 세션 정책

- 내부 알파 세션은 로그인 성공 시 시작하고 마지막 인증 활동으로부터 7일 동안 유지한다.
- 7일 동안 활동이 없거나 계정 접근이 회수되면 세션을 만료하고 다시 로그인을 요구한다.
- 로그아웃은 현재 세션을 서버에서 즉시 무효화한다. 무효화된 세션의 조회와 변경 요청은
  성공 형태로 처리하지 않는다.
- 세션이 저장 도중 만료되면 서버는 변경을 적용하지 않고 인증 만료를 알린다. 클라이언트는
  사용자가 작성 중인 입력을 화면에 유지해 재로그인 후 다시 시도할 수 있게 한다.
- 세션 식별자와 인증 비밀은 URL, 애플리케이션 로그, 분석 이벤트와 저장소에 평문으로 남기지
  않는다.
- 여러 기기 로그인을 허용하되 각 로그아웃은 현재 기기 세션만 종료한다. 전체 기기 로그아웃,
  기기 목록과 원격 세션 해제는 Later다.

### 기록과 버전 정책

- 수정은 과거 버전을 덮어쓰지 않는다. 과거 버전에는 당시 값, 당시 맥락과 기록 시점만 보존한다.
- 과거 버전은 소유자만 볼 수 있고 개별 버전을 따로 공개하거나 수정하지 않는다.
- 공개 프로필은 승인된 현재 버전만 보여주며, 버전 이력의 존재 여부도 방문자에게 노출하지 않는다.
- 두 세션의 수정이 겹치면 나중 요청이 조용히 앞선 내용을 덮어쓰지 않도록 충돌을 알린다.

### 분석과 관측 정책

- 질문 식별자, 성공·실패 상태, 소요 구간과 공개 설정 변경 여부처럼 기능 검증에 필요한 최소
  이벤트만 수집한다.
- 자유 서술 원문, 선택 답변 값, 성격·약점·감정, 공개 slug, 계정 이메일과 세션 식별자는 분석
  이벤트나 오류 로그의 속성으로 보내지 않는다.
- 비공개 필드가 공개 응답에 포함된 사건과 삭제 후 재노출은 건수와 무관하게 즉시 중단·조사할
  보안 사건으로 다룬다.

## 인수 기준

### P0 핵심 여정

1. 유효한 내부 계정은 로그인할 수 있고 잘못된 계정 정보는 계정 존재 여부를 드러내지 않는다.
2. 질문을 모두 건너뛰어도 진행이 막히지 않으며, 답한 질문만 기록으로 생성된다.
3. 새 기록은 서버에 `private`로 저장되고 앱, 세션과 서버를 다시 시작한 뒤에도 같은 소유자에게
   보인다.
4. 다른 사용자와 비로그인 방문자는 소유자의 비공개 기록 및 존재 여부를 받을 수 없다.
5. 기록을 수정하면 직전 값과 맥락, 시점이 과거 버전으로 보존되고 현재 값만 바뀐다.
6. 공개 중인 항목을 수정하면 즉시 `private`로 바뀌며 수정 전·후 원문 모두 공개 응답에서 빠진다.
7. 오래된 버전에 기반한 수정은 충돌로 거절되고 앞선 저장과 사용자의 미제출 입력을 모두 잃지 않는다.
8. 사용자는 항목을 선택하고 방문자와 동일한 결과를 미리 본 뒤에만 공개할 수 있다.
9. 공개 응답의 JSON과 화면에는 공개 현재 값 외에 비공개 항목, 과거 버전, 근거, 변화 이유,
   다음 시도, 이메일과 내부 식별자가 없다.
10. 비로그인 방문자는 공개 URL에서 공개 항목을 볼 수 있고 공개 항목이 없으면 안전한 빈 상태를 본다.
11. 공개 해제 성공 직후 새 공개 조회에서 해당 항목이 사라지고 개인 기록과 버전은 유지된다.
12. 개별 삭제 성공 후 현재 기록, 모든 버전과 공개 응답에서 항목이 사라지며 재로그인과 서버
    재시작 후에도 복원되지 않는다.
13. 인증 만료, 권한 없음, 검증 오류, 충돌과 서버 오류는 구분되며 실패한 변경을 성공처럼 표시하지 않는다.
14. 저장·수정·공개·삭제의 중복 제출을 막고 실패 시 사용자가 작성 중인 입력을 유지한다.
15. 키보드와 스크린리더로 전체 여정을 수행할 수 있고 200% 글자 확대와 축소 모션 설정에서도
    핵심 행동과 상태 메시지에 접근할 수 있다.

### P0 권한·프라이버시 검증

1. 권한 행렬의 모든 불가 조합을 자동 테스트하고 소유자 응답과 공개 응답 스키마를 별도로 검증한다.
2. 사용자 A의 인증 정보로 사용자 B의 기록 ID를 조회·수정·삭제·공개하려는 모든 요청이 실패한다.
3. 공개 범위는 클라이언트 표시 상태와 관계없이 서버에서 최종 강제한다.
4. 공개 해제와 삭제 후 브라우저의 새 요청, 서버 캐시와 공개 투영에 이전 원문이 없다.
5. 애플리케이션 로그, 오류 응답, 분석 이벤트와 URL에 자유 서술 원문 및 인증 비밀이 없다.
6. 계정 접근 회수, 로그아웃과 7일 비활동 만료 후 기존 세션으로 소유자 API를 사용할 수 없다.

### 출시 차단 조건

- 비공개 필드가 공개 응답 또는 다른 사용자 응답에 한 번이라도 포함된다.
- 수정, 공개 해제 또는 삭제 성공 응답 후 서버 재시작으로 이전 상태가 되살아난다.
- 삭제한 원문 또는 버전이 소유자·공개 API, 캐시나 분석·오류 로그에서 다시 조회된다.
- 인증되지 않은 요청 또는 다른 사용자가 기록을 생성·변경·삭제하거나 버전 이력을 조회한다.
- 미리보기와 실제 공개 URL의 내용 또는 공개 범위가 다르다.
- 핵심 여정의 오류가 사용자 입력을 잃게 하거나 실패를 성공으로 표시한다.

## 지표

내부 알파는 체류 시간, 작성 글 수와 공개 항목 수를 성공 지표로 사용하지 않는다. 다음 지표는
자유 서술 원문이나 답변 값을 수집하지 않고 이벤트와 선택적 설문을 결합해 본다.

- `보존 신뢰`: 저장 24시간 이후 재방문한 테스터 중 이전 기록을 문제없이 확인한 비율과
  "내 기록이 안전하게 보존된다고 느낀다" 응답
- `자기이해 도움`: 핵심 여정 후 "현재의 나를 설명하는 데 도움이 됐다" 5점 척도와 이유에
  대한 선택적 인터뷰
- `회고 행동`: 첫 기록 후 7일 안에 과거 기록을 다시 보고 맥락을 추가하거나 수정한 테스터 비율
- `변화 안전감`: 버전 이력을 본 사용자의 "변화가 평가받기보다 맥락으로 보였다" 응답
- `공개 확신`: 공개 미리보기를 본 테스터의 "누가 무엇을 보게 되는지 확신했다" 응답과 의도치
  않은 공개 신고 건수
- `프라이버시 무결성`: 권한 테스트 통과율 100%, 비공개 필드 노출·삭제 후 재노출 사건 0건
- `핵심 여정 신뢰성`: 로그인부터 삭제까지 과업 성공률, 단계별 실패율과 재시도 성공률

알파 종료 시 가설별 결과를 `지지`, `기각`, `판단 보류`로 기록하며, 공개 항목 수가 적다는 이유로
공개를 더 강하게 유도하지 않는다.
