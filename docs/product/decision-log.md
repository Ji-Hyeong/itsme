## D-006: 제품 Client와 Backend 기술 스택

- 날짜: 2026-07-14
- 상태: 승인
- 결정: 제품 Client는 Expo React Native를 유지하고, Backend는 Kotlin과 Spring Boot 기반
  모듈형 모놀리스와 PostgreSQL·Flyway로 구현한다.
- 계약: Client와 Backend는 OpenAPI를 단일 진실 공급원으로 사용하며 서버 interface, DTO,
  TypeScript client와 validator를 생성한다.
- 배포 전 조건: iOS bundle identifier, Android package, EAS 환경별 build profile, 앱 자산,
  권한 설명, 딥 링크와 서명 자격 증명 관리 방식을 확정한다.
- 근거: `docs/architecture/decisions/0002-client-and-backend-stack.md`에 기록한다.

## D-007: 내부 알파 검증 범위

- 날짜: 2026-07-22
- 상태: 승인
- 결정: 초대 계정의 로그인부터 질문, 영구 저장, 수정과 버전, 공개 선택, 공개 URL,
  공개 해제와 개별 기록 삭제까지를 내부 알파의 하나의 핵심 여정으로 검증한다.
- 제외: 자가 가입, 비밀번호 재설정, 계정 삭제 셀프서비스, 제한 공개, 오프라인 동기화와
  소셜 기능은 내부 알파 범위에 포함하지 않는다.
- 근거: `docs/product/internal-alpha.md`에 범위, 정책과 인수 기준을 기록한다.

## D-008: 공개 항목 수정 시 공개 해제

- 날짜: 2026-07-22
- 상태: 승인
- 결정: 공개 중인 기록을 수정하면 해당 항목을 `private`로 바꾸고 공개 응답에서 제거한다.
  사용자가 새 내용을 미리 본 뒤 다시 명시적으로 공개해야 한다.
- 근거: 기록 저장과 공개를 분리하고, 이전 공개 동의가 새 원문에 자동 적용되는 것을 막는다.
- 검토한 대안: 이전 공개 버전을 계속 보여주는 방식은 별도 발행 스냅샷과 상태 설명이 필요하고,
  수정값을 즉시 공개하는 방식은 공개 원칙을 위반하므로 내부 알파에서 채택하지 않는다.

## D-009: 내부 알파 개별 기록 삭제

- 날짜: 2026-07-22
- 상태: 승인
- 결정: 개별 기록 삭제는 현재 값, 모든 과거 버전, 맥락과 파생 공개 데이터를 함께 영구
  제거하며 앱 내 복구를 제공하지 않는다. 공개 해제는 기록과 버전을 유지하는 별도 행동이다.
- 후속 확인: 정식 출시 전 법정 보존 대상, 삭제 유예, 백업 최대 삭제 기한과 계정 삭제 정책을
  별도로 승인한다.

## D-010: 내부 알파 세션 운영 정책

- 날짜: 2026-07-22
- 상태: 내부 알파 한정 승인
- 결정: 세션은 마지막 인증 활동 후 7일에 만료하고, 로그아웃과 계정 접근 회수 시 서버에서
  무효화한다. 여러 기기 세션은 허용하되 로그아웃은 현재 기기 세션만 종료한다.
- 후속 확인: 정식 출시의 세션 수명, 전체 기기 로그아웃, 비밀번호 재설정과 다중 인증은 인증
  방식 및 위협 모델과 함께 재검토한다.
