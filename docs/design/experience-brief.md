# 나의 장면 경험 브리프

이 문서는 잇츠미 첫 프로토타입에서 검증할 감정적 목표와 화면 행동을 정의한다. 확정된
시각·상호작용 명세는 `prototype-v1.md`를 따른다. 현재 구현된 `나`, `질문`, `변화`,
`공개`의 네 여정을 더 자연스럽고 완성도 있게 연결하며 새로운 사업 기능은 추가하지 않는다.

## 경험 목표

사용자가 잇츠미를 열었을 때 `프로필을 완성해야 한다`가 아니라 `지금의 나를 한 장면씩
바라볼 수 있다`고 느껴야 한다. 한 단어와 짧은 문장도 충분한 기록이며, 사진이나 긴 글이
없어도 화면은 개인적이고 완성된 인상을 준다.

경험을 설명하는 세 단어는 `차분한`, `개인적인`, `변화 가능한`이다. 경쟁적인, 진단하는,
과시하는 경험은 만들지 않는다.

## 핵심 모델: 나의 장면

`나의 장면`은 현재의 나를 고정된 소개문이나 여섯 칸의 완성표가 아니라, 서로 다른 시기의
짧은 문장이 모여 이루는 초상으로 읽는 방식이다. 취향, 성격, 가치, 강점, 배우는 중인 것과
도움이 필요한 것은 우열 없이 동등한 장면이 된다.

질문에 답하면 새 장면이 현재의 나에 놓인다. 답을 바꾸면 이전 장면을 지우거나 덮어쓰지
않고 변화 화면에 당시 문장과 시점을 보존한다. 비어 있는 범주는 결핍이나 미완성이 아니라
지금은 말하지 않기로 한 상태다. 범주 수, 기록 수와 공개 수를 점수·진행률·성과 지표로
표현하지 않는다.

## 한국 서비스에서 차용한 원리

아래 사례의 사업 모델이나 소셜 지표를 복제하지 않고, 한국 사용자가 이미 익숙하게 받아들이는
입력 부담, 문장 위계와 개인 화면 구성 원리만 적용한다.

- [리틀리](https://start.litt.ly/solution/portfolio): 적은 블록과 짧은 설정만으로 공유 가능한
  개인 페이지가 완성되는 원리. 분석·판매 도구는 적용하지 않는다.
- [문토](https://people.munto.kr/munto): 취향을 타인에게 평가받는 정보가 아니라 나를 발견하는
  출발점으로 설명하는 생활 언어. 모임·피드·관계 수치는 적용하지 않는다.
- [왓챠피디아](https://apps.apple.com/kr/app/id644185507): 한 번의 선택만으로 기록이 성립하고,
  원할 때 한 줄이나 긴 감상을 더하는 점진적 입력. 별점·예상 점수·추천은 적용하지 않는다.
- [브런치스토리](https://brunch.co.kr/ready): 넓은 여백과 명확한 한글 위계로 짧은 글도 하나의
  작품처럼 읽히게 하는 편집 리듬. 인기·구독·후원 지표는 적용하지 않는다.
- [29CM](https://www.29cm.co.kr/content/pt/2023/03/31/pottery): 여러 카드를 빽빽하게 나열하기보다
  제목, 짧은 본문과 여백으로 하나의 이야기에 집중시키는 구성.
- [하루콩](https://apps.apple.com/kr/app/id1553223828): 몇 번의 탭으로 기록을 시작하고 축적된
  흐름을 한눈에 돌아보는 낮은 진입 부담.
- [세줄일기](https://apps.apple.com/kr/app/id1436460302): 짧은 입력도 한 권의 기록처럼 보이게
  만들어 분량보다 지속과 보존에 의미를 주는 원리.

## 핵심 여정

### 1. 비어 있어도 온전한 나를 만난다

첫 `나` 화면은 `아직 말로 정하지 않은 나도 괜찮아요`라는 제목, 질문을 시작하는 한 개의
행동과 범주 안내로 구성한다. 여섯 개의 빈 칸을 반복하거나 완성률을 보여주지 않는다.
기록이 없어도 여백, 제목과 한 문장으로 의도적으로 완성된 장면처럼 보여야 한다.

### 2. 질문 하나와 머문다

한 화면에는 질문 하나만 보여준다. 먼저 탭으로 답할 수 있는 선택을 제공하고, 사용자가
원할 때만 `내 말로 쓰기`와 맥락 입력을 연다. 사용자는 언제든 `지금은 건너뛸게요`를 선택할
수 있다. 저장 행동 가까이에서 `처음에는 나만 볼 수 있어요`를 확인한다.

### 3. 현재의 나에서 답을 다시 읽는다

저장 직후 사용자의 답이 `나` 화면의 새 장면으로 나타난다. 시스템의 카테고리명보다
사용자의 문장이 먼저 읽혀야 한다. 짧은 답은 여백과 활자로, 긴 답은 일부 내용과 `이어 읽기`로
완성도 있게 표현하며 별도 장식 캔버스와 목록을 중복 제공하지 않는다.

### 4. 변화를 판단 없이 돌아본다

기존 답을 갱신할 때 현재 답, 변화 이유와 다음 시도를 분리해 입력한다. 변화 화면은 이전과
현재 문장을 시간 순서로 보여주되 좋아짐, 나빠짐, 상승, 하락이나 성장 점수를 사용하지 않는다.

### 5. 보여줄 나를 직접 선택한다

사용자는 항목별 공개 상태를 변경하고 방문자가 실제로 보는 것과 같은 화면을 확인한 뒤
공유한다. 공개 항목이 없어도 정상 상태다. 비공개 답변, 과거 버전과 작성 맥락은 공개 응답과
화면에 존재하지 않아야 한다.

## 화면별 감정과 행동

| 화면 | 사용자가 느껴야 하는 것 | 가장 중요한 행동 | 피해야 하는 것 |
| --- | --- | --- | --- |
| 나 | 짧은 말도 지금의 나를 충분히 보여줌 | 장면 읽기 또는 질문 시작 | 빈 칸 반복, 완성도 |
| 질문 | 답을 강요받지 않고 잠시 생각할 수 있음 | 저장 또는 건너뛰기 | 설문 진행률, 영문 상태 |
| 변화 | 과거와 현재가 모두 유효함 | 맥락 읽기·남기기 | 상승·하락, 연속 기록 |
| 공개 | 무엇이 보이는지 확신할 수 있음 | 미리보기 후 공유 | 공개 유도, 반응 지표 |

## 시각적 인상

클라우드 그레이와 화이트를 넓게 사용하고, 인디고·세이지·살구는 선택, 범주 표식과 변화의
작은 단서에만 절제해 사용한다. 둥근 모듈과 충분한 여백이 장면 사이의 호흡을 만들며 굵은
검정 구조선, 형광색 대면적, 포스터처럼 과장된 영문 타이포를 사용하지 않는다.

표시와 본문 모두 현대적인 한글 산세리프를 사용한다. 제목은 크기와 굵기로 존재감을 만들되
사용자의 답을 압도하지 않는다. `LIVE INDEX`, `SIGNAL`, `SELECTED`, `PRIVATE`, `PUBLIC`,
`STORIES` 같은 제품·상태 용어는 화면에서 제거하고 `현재의 나`, `선택됨`, `나만 보기`,
`공개`, `개의 공개된 이야기`처럼 자연스러운 한국어로 표현한다. 항목 수 문구는 공개 결과를
이해하는 데 꼭 필요한 경우에만 사용하며 성과 지표처럼 강조하지 않는다.

## 내비게이션 경험

현재 구현 범위를 존중해 네 탭 `나`, `질문`, `변화`, `공개`를 유지한다. 기존 `발견`은
행동이 더 분명한 `질문`으로 바꾼다. 모바일은 안전 영역을 포함한 고정 하단 탭, 데스크톱은
동일한 순서와 용어를 사용하는 왼쪽 내비게이션으로 확장한다. 활성 탭은 아이콘, 글자 굵기와
작은 인디고 표식을 함께 사용하며 색만으로 구분하지 않는다.

## 콘텐츠 원칙

- 사용자의 말을 고치거나 더 긍정적인 표현으로 자동 변환하지 않는다.
- `완성`, `부족`, `성공`, `성장률`처럼 평가나 채우기를 암시하는 단어를 사용하지 않는다.
- 행동 문구는 `질문 하나 만나기`, `나만 보기로 남기기`, `지금은 건너뛸게요`,
  `공개 모습 미리보기`처럼 결과를 구체적으로 설명한다.
- 약점은 `배우는 중`, `도움이 있으면 좋은 것`, `지금은 우선순위가 아닌 것`처럼 맥락과
  변화 가능성을 담아 표현한다.
- MBTI는 `요즘의 나를 표현하는 참고 정보`로 설명하고 진단·판정 문구를 쓰지 않는다.
- 공개 항목 없음, 과거 기록 없음과 질문 건너뛰기를 정상적인 선택으로 서술한다.

## 필수 상태

- 기록 없음, 한 개 기록과 세 개 이상 범주의 기록
- 일부 질문을 건너뛴 상태와 동일 질문의 과거 버전이 있는 상태
- 한 단어 답변, 두 줄 답변과 600자 답변
- 공개 항목 없음, 일부 공개, 공개 해제 직후와 권한 없음
- 초기 로딩, 저장 중, 불러오기 실패, 저장 실패와 재시도
- 삭제 확인, 삭제 중, 삭제 실패와 삭제 완료
- 작은 모바일, 태블릿, 데스크톱, 200% 확대, 스크린리더와 축소 모션

## 접근성 경험 기준

사용자는 색을 보지 못해도 범주와 상태를 이해하고, 키보드와 스크린리더로 질문 답변부터
공개 미리보기까지 완료할 수 있어야 한다. 200% 확대에서는 모듈이 자연 높이의 단일 열로
바뀌며 사용자 텍스트가 겹치거나 잘리지 않아야 한다. 모든 저장과 공개 변경은 시각 피드백과
접근성 알림을 함께 제공하고 축소 모션에서는 위치 이동 없이 결과를 전달한다.

## 검증 질문

- 빈 `나` 화면만 보고도 자기 기록 도구라는 사실과 첫 행동을 이해하는가?
- 한 개의 짧은 답만 있어도 화면이 완성된 개인 장면처럼 느껴지는가?
- 여백, 둥근 모듈과 절제된 색이 차분하되 흔한 카드 대시보드처럼 보이지 않는가?
- 사용자는 범주 수를 점수나 프로필 완성도로 오해하지 않는가?
- 질문을 건너뛰어도 진행이 막히거나 죄책감을 느끼지 않는가?
- 현재 답과 과거 답, 나만 보기와 공개 상태를 혼동하지 않는가?
- 공개 전 방문자가 보게 될 정보를 확신할 수 있는가?
- 모바일과 데스크톱 모두 타인을 위한 SNS보다 나를 위한 기록 공간으로 느껴지는가?
