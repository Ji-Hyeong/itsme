# 모바일 재설계 스프린트 1

## 문서 목적

이 문서는 `나`, `질문`, `변화`, `공개 선택`, `공개 미리보기`, `기록 상세`의 모바일 구현
계약이다. 기능을 추가하는 스프린트가 아니라, 현재 MVP를 `나의 장면`이라는 하나의 시각·행동
언어로 정리하고 `docs/design/design-quality-gate.md`를 통과할 수 있는 상태로 만드는 스프린트다.

상위 기준은 `docs/product/vision.md`, `docs/product/principles.md`, `docs/product/mvp.md`,
`docs/design/brand.md`, `docs/design/design-quality-gate.md`다. 충돌하면 제품 원칙과 개인정보
보호를 우선하고, 제품 정책은 PO가 최종 결정한다.

## 스프린트 목표와 비목표

### 목표

- 사용자의 현재 문장을 화면에서 가장 강한 정보로 만든다.
- 짧은 기록 하나와 빈 상태도 완성된 개인 화면처럼 보이게 한다.
- 정상·빈·로딩·오류·권한 없음·긴 콘텐츠를 같은 수준의 완성도로 제공한다.
- 이름·intro의 공개와 기록별 공개를 사용자가 오해하지 않게 한다.
- 390×844와 430×932, 600자 답변과 200% 글자 확대에서 핵심 여정을 끝낼 수 있게 한다.
- 공용 primitive와 token으로 화면별 임의 스타일을 제거한다.

### 비목표

- 좋아요, 팔로워·팔로잉, 조회수, 인기 순위, 궁합·성장 점수와 프로필 완성률
- 기록 수를 성과로 보이게 하는 badge, 진행률, 경쟁형 연속 기록
- 공개를 유도하는 알림, 추천, 기본 공개와 반응 수집
- AI 성격 진단, 평가, 자동 긍정 표현 변환
- 사진, 꾸미기와 장문을 요구하는 프로필 제작 도구

## 사용자 흐름과 화면 책임

| 화면 | 목적 | 진입 | 성공 이탈 | 안전 이탈 |
| --- | --- | --- | --- | --- |
| 나 | 현재의 이름·intro와 기록을 읽음 | 로그인 완료, 하단 `나` | 질문, 기록 상세, 공개 선택 | 계정, 앱 종료 |
| 질문 | 질문 하나와 머물고 답을 나만 보기로 저장함 | 하단 `질문`, 빈 나 CTA | 저장 후 다음 질문 또는 나 | 건너뛰기, 닫기 |
| 변화 | 이전과 현재 문장을 판단 없이 돌아봄 | 하단 `변화` | 기록 상세 | 하단 다른 탭 |
| 공개 선택 | 기록별 공개 범위를 선택함 | 하단 `공개`, 상세의 공개 행동 | 공개 미리보기 | 변경 취소, 다른 탭 |
| 공개 미리보기 | 방문자와 동일한 결과를 확인함 | 공개 선택, 나의 보조 행동 | 최종 공개 또는 방문자 화면 | 선택으로 돌아가기 |
| 기록 상세 | 현재 답과 과거 버전을 읽고 수정·삭제함 | 나의 SceneCard, 변화의 기록 | 새 버전 저장, 공개 선택 | 뒤로가기, 편집 취소 |

하단 탭은 `나`, `질문`, `변화`, `공개` 순서를 유지한다. 기록 상세와 공개 미리보기는 하단
탭보다 현재 작업의 뒤로가기·닫기 행동을 우선한다. 사용자가 저장하지 않고 나갈 때 입력이
있다면 삭제 여부를 묻지 말고 `계속 쓰기`와 `나가기`를 제공한다.

## 공개 정책과 고정 문구

이번 스프린트의 화면 계약은 다음과 같다.

화면 위치에 따라 아래 문구를 그대로 사용한다.

- 나 cover: `이름과 한 줄 소개는 공개 프로필에 보여요.`
- 나 기록 섹션: `아래 기록은 항목마다 공개 범위를 고를 수 있어요. 새 기록은 나만 보기로 시작해요.`
- 공개 선택 상단: `이름과 한 줄 소개는 기본으로 보여요. 아래 기록만 하나씩 공개하거나 숨길 수 있어요.`
- 공개 미리보기의 공개 기록 없음 안내: `이름과 한 줄 소개만 보여요. 공개한 기록은 아직 없어요.`
- 방문자 profile의 기록 빈 상태: `공개한 기록은 아직 없어요.`

- `이름`과 작성된 `intro`는 공개 프로필의 기본 정보다.
- 기록은 새로 저장할 때 항상 `나만 보기`이며 항목별로만 `공개`로 바꿀 수 있다.
- 소유자 cover 전체에 `나만 보기` badge를 붙이지 않는다. cover 아래에 위 고정 문구를 정보
  아이콘과 함께 표시한다.
- intro가 비어 있으면 공개 화면에서 빈 줄이나 자리표시를 만들지 않는다.
- 공개 응답에는 공개한 현재 기록만 포함한다. 비공개 기록, 과거 버전, 변화 이유, 다음 시도,
  작성 맥락과 내부 ID는 포함하지 않는다.
- 공개 전환은 확인 후 미리보기, 최종 공개의 두 단계다. 미리보기와 방문자 화면은 같은 공개
  응답과 `PublicProfileView` 계열 renderer를 사용한다.
- `/p/{slug}`가 바뀌면 이전 공개 프로필을 즉시 비우고 skeleton을 표시한다. 늦게 끝난 이전
  요청은 현재 slug와 일치하지 않으면 버린다.

## 레이아웃 계약

### 모바일 프레임

| viewport | 좌우 gutter | 콘텐츠 폭 | 열 | 하단 탭 |
| --- | --- | --- | --- | --- |
| 390×844 | 20pt | 350pt | 1열 | 64pt + bottom safe area |
| 430×932 | 20pt | 390pt | 1열 | 64pt + bottom safe area |

- 화면 콘텐츠는 항상 너비 100%다. 430pt에서도 다열, 좁은 카드와 내용 폭 CTA로 바꾸지 않는다.
- 상단 safe area 다음 첫 콘텐츠 여백은 16pt, 일반 화면 마지막 여백은 40pt다.
- 고정 하단 탭이 있는 화면은 scroll content에 `64pt + bottom safe area + 24pt` 이상의 하단
  padding을 둔다. `BottomActionBar`가 있으면 그 실제 높이도 더한다.
- Web preview는 최대 480px의 모바일 프레임만 제공한다. 데스크톱 다열은 이번 범위가 아니다.
- 사용자 콘텐츠에 absolute position을 사용하지 않는다.

### 200% 확대 전환

`fontScale >= 1.5`부터 확대 레이아웃을 사용하고 2.0에서 최종 검증한다.

- 화면 제목 옆 action, SceneCard header·footer, timeline 날짜와 본문을 세로로 쌓는다.
- 텍스트 줄 수 제한과 고정·최대 높이를 제거한다.
- 두 버튼은 가로 배치하지 않고 각 100% 폭의 세로 순서로 둔다.
- `BottomActionBar`는 overlay 고정을 해제하고 scroll content 마지막의 in-flow 영역으로 전환한다.
- modal은 화면 좌우 20pt, 상하 safe area를 제외한 범위에서 내부 스크롤을 허용한다.
- 글자 크기 배율을 임의로 제한하지 않는다. 가로 스크롤, 텍스트 겹침과 잘린 CTA를 허용하지 않는다.

## 디자인 token

구현은 아래 semantic token만 사용한다. 기존 token 값이 다르면 이 표를 기준으로 한 번에
정렬하며 화면 파일에 새 hex, 글자 크기, radius를 직접 추가하지 않는다.

### 색

| token | 값 | 용도 |
| --- | --- | --- |
| `color.canvas` | `#F4F5F7` | 앱 배경 |
| `color.surface` | `#FFFFFF` | 카드, 입력, modal |
| `color.surfaceMuted` | `#EEF0F3` | 비활성·skeleton 면 |
| `color.ink` | `#24262B` | 제목, 본문 |
| `color.muted` | `#666B73` | 보조 설명 |
| `color.lineSubtle` | `#DDE0E5` | 장식용 divider, 의미를 단독 전달하지 않음 |
| `color.lineStrong` | `#777B83` | 입력·control 경계, 3:1 이상 필요한 구조선 |
| `color.indigo` | `#4457A6` | 주요 행동, 선택, 활성 탭 |
| `color.indigoDeep` | `#344383` | 흰 바탕의 작은 강조 텍스트 |
| `color.indigoSoft` | `#EEF0FA` | 선택된 option 배경 |
| `color.sage` | `#718477` | 범주 단서, 큰 텍스트가 아닌 표식 |
| `color.sageSoft` | `#EDF2EE` | 낮은 강조 면 |
| `color.apricot` | `#C87D5B` | 변화 시점 표식 |
| `color.apricotSoft` | `#FAEFEA` | 변화 맥락 면 |
| `color.error` | `#B3261E` | 오류·파괴 행동 |
| `color.errorSoft` | `#FCEDEA` | 오류 배경 |
| `color.scrim` | `rgba(36,38,43,0.56)` | BlockingDialog 배경 |
| `color.focus` | `#254FB5` | 3pt 포커스 outline |

일반 텍스트는 배경과 4.5:1, 큰 텍스트·아이콘·의미 있는 구조선·포커스는 3:1 이상이어야 한다.
`lineSubtle`은 간격이나 표면 차이가 이미 구조를 전달할 때만 쓴다. Indigo, Sage, Apricot의
합산 면적은 한 화면의 약 10%를 넘지 않는다.

### 타이포그래피

기본 글꼴은 로컬 번들 `Pretendard` Regular·Medium·SemiBold·Bold이고 fallback은 플랫폼 sans-serif다. 이름,
사용자 답변, UI를 다른 글꼴로 분리하지 않고 크기·굵기·여백으로 위계를 만든다.

| token | size/line | weight | 용도 |
| --- | --- | --- | --- |
| `type.profileName` | 32/42 | 700 | 이름 |
| `type.question` | 32/42 | 700 | 질문 한 문장 |
| `type.screenTitle` | 28/38 | 700 | 화면 제목 |
| `type.sceneAnswer` | 24/36 | 700 | 현재 답변 |
| `type.sectionTitle` | 22/31 | 700 | 섹션 제목 |
| `type.body` | 16/26 | 400 | 본문, intro |
| `type.control` | 15/22 | 600 | 버튼, option |
| `type.meta` | 12/18 | 500 | 범주, 날짜, 상태 |

제목 자간은 `-0.02em` 이내, 나머지는 0이다. 영문 대문자 eyebrow와 넓은 자간은 사용하지
않는다. 사용자 원문의 줄바꿈은 보존하고 앱이 표현을 교정하지 않는다.

### 공간·크기·radius

- spacing: `4, 8, 12, 16, 20, 24, 32, 40, 48pt`
- minimum touch target: `44×44pt`
- 기본 control: 높이 `52pt`, 좌우 padding `16pt`, radius `14pt`
- 질문 option: 최소 높이 `60pt`, padding `16pt`, radius `14pt`
- SceneCard: 최소 높이 `168pt`, padding `20pt`, radius `18pt`, 카드 간 `12pt`
- 공개 SceneCard: 최소 높이 `144pt`
- profile cover: 390pt에서 `350×280pt`, padding `24pt`, radius `24pt`
- StatePanel: 최소 높이 `168pt`, padding `20pt`, radius `18pt`
- BlockingDialog: 좌우 `20pt`, 최대 너비 `390pt`, padding `24pt`, radius `24pt`
- 포커스: `3pt` outline, 바깥 offset `2pt`; border 두께 변화로 layout을 움직이지 않음
- 그림자, 2pt 이상의 구조선, 배경 gradient와 glow를 사용하지 않는다.

## 공용 primitive 명세

### `ScreenHeader`

- 구성: 선택적 back action, `type.screenTitle`, 선택적 설명, 최대 한 개의 trailing action.
- 제목과 설명의 간격은 8pt, header 아래 첫 섹션은 24pt다.
- back과 trailing action은 최소 44×44pt이며 텍스트 action은 자연 폭을 허용한다.
- 100%에서는 제목과 action을 같은 행에 둘 수 있다. `fontScale >= 1.5`에서는 action을 다음 행
  오른쪽 또는 100% 폭으로 내려 제목을 침범하지 않는다.
- 접근성 heading은 화면마다 하나다. back action은 목적지를 포함한 이름을 갖는다.

### `SceneCard`

- 정보 순서: 범주 → 현재 답변 → 선택적 제목·날짜 → 공개 상태. 사용자 답변이 가장 크다.
- 범주색은 상단 4pt bar 또는 8pt 점 중 하나만 사용하고 아이콘·배경색과 중복하지 않는다.
- 소유자 card 전체가 기록 상세로 이동하는 하나의 44pt 이상 button이다.
- `나만 보기`는 자물쇠와 텍스트, `공개`는 눈 아이콘과 텍스트를 함께 쓴다.
- 100%에서 답변은 네 줄 후 `이어 읽기`를 제공한다. 확대·스크린리더에서는 줄임을 제거한다.
- 첫 카드, 공개 카드와 비공개 카드의 크기를 달리해 우열을 만들지 않는다.
- 접근성 이름은 `범주, 답변, 공개 상태, 마지막 변경일` 순서다.

### `BottomActionBar`

- 화면 좌우 20pt 기준, surface 배경, 상단 1pt `lineSubtle`, 내부 상하 12pt다.
- 주요 버튼 한 개는 높이 52pt, 너비 100%다. 보조 행동은 그 아래 44pt text button으로 둔다.
- 하단 탭 화면에서는 탭 바로 위, modal·미리보기 화면에서는 bottom safe area 위에 둔다.
- scroll content의 마지막 요소가 bar 뒤에 숨지 않도록 실제 bar 높이만큼 padding을 계산한다.
- 키보드가 열리면 키보드 위로 이동한다. 600자와 `fontScale >= 1.5`에서는 in-flow로 전환한다.
- 저장 중에는 입력을 유지하고 버튼 문구를 `남기는 중…`으로 바꾸며 중복 제출을 막는다.

### `StatePanel`

- variant: `empty`, `loading`, `error`, `permission`, `noPublicRecords`.
- 정보 순서: 상태 아이콘 또는 skeleton → 22/31 제목 → 16/26 설명 → 선택적 52pt action.
- empty는 성공·미완성 언어를 쓰지 않는다. error는 원인을 추측하지 않고 재시도 결과를 보장하지 않는다.
- loading은 최종 화면과 같은 개수·높이의 정적 skeleton을 사용한다. 사용자 데이터처럼 보이는
  임시 문구와 무한 shimmer를 사용하지 않는다.
- error와 permission은 `accessibilityRole=alert` 또는 live region으로 한 번 알리고 안전한 이탈을 제공한다.

### `BlockingDialog`

- 삭제와 공개 전환처럼 되돌리기 어렵거나 개인정보 범위가 바뀌는 결정에 사용한다.
- 제목, 대상 현재 문장, 결과 설명, 취소, 확정 순서다. 파괴 행동은 마지막에 둔다.
- 배경 조작을 막고 스크린리더에서 dialog 밖 요소를 숨긴다. 열릴 때 제목으로 포커스를 옮기고,
  닫힌 뒤 실행 control로 돌려보낸다.
- 내용이 길거나 200% 확대이면 dialog body만 세로 스크롤한다. 제목과 행동을 잘라내지 않는다.
- Android back과 iOS escape gesture는 취소와 같고 저장·삭제 중에는 중복 확정을 막는다.
- 삭제 실패 시 dialog를 닫거나 목록에서 먼저 제거하지 않고 원문과 오류를 보존한다.

## 화면별 재설계

### 1. 나

#### 정보 구조

1. `ScreenHeader`: `지금의 나`, trailing `계정`
2. profile cover: 이름, 선택적 intro
3. cover 공개 안내: `이름과 한 줄 소개는 공개 프로필에 보여요.`
4. `내가 남긴 장면`과 기록 안내: `아래 기록은 항목마다 공개 범위를 고를 수 있어요. 새 기록은 나만 보기로 시작해요.`
5. 답이 있는 `SceneCard` 목록
6. `더 알아보고 싶은 나`: 질문 진입 한 개
7. 보조 행동 `공개 모습 미리보기`

정상 상태에서 cover는 Scene M, 큰 badge와 avatar를 동시에 쓰지 않는다. Scene M을 쓰면 40pt
컬러 심볼 한 번만 사용하고 이름보다 약하게 보이게 한다. intro가 없으면 대체 문구를 공개
데이터처럼 cover 안에 넣지 않는다.

빈 상태는 cover와 공개 정책 안내를 유지하고 `StatePanel`에 `아직 말로 정하지 않은 나도
괜찮아요`, `지금 답하기 편한 질문 하나부터 만나보세요.`, `질문 하나 만나기`를 제공한다.
빈 범주 카드, `0/6`과 완성률은 없다.

로딩은 cover skeleton 280pt와 SceneCard skeleton 2개, 오류는 같은 목록 위치의 error
StatePanel과 `다시 불러오기`를 사용한다. 캐시가 있으면 기존 사용자 문장을 유지하고 비파괴적
오류 panel을 목록 위에 표시한다.

### 2. 질문

#### 정보 구조

1. `ScreenHeader`: `질문`, trailing `닫기`
2. 범주 meta: `취향에 관한 질문`
3. 질문 한 문장과 선택적 안내
4. 선택 option 또는 자유 입력
5. 선택 후 선택적 `조금 더 남기고 싶다면` 맥락 입력
6. `BottomActionBar`: `나만 보기로 남기기`, `지금은 건너뛸게요`

진행률, `01/06`, 완료 표현은 없다. 선택 option은 최소 60pt이며 선택 시 Indigo Soft, 체크,
`선택됨`을 함께 표시한다. 모든 질문은 건너뛰고 닫을 수 있다.

자유 입력은 최대 600자, 최소 높이 168pt다. counter는 입력 아래 오른쪽에 `0/600`으로 표시하고
label·도움말·counter·오류를 프로그램적으로 연결한다. 540자와 600자에서만 남은 분량을
접근성 알림으로 전달해 입력마다 읽지 않는다. 100%에서는 입력 높이를 최대 320pt로 제한하고
내부 스크롤할 수 있다. `fontScale >= 1.5`에서는 최대 높이를 제거하고 화면 scroll만 사용한다.

질문 로딩은 category 24pt, 질문 2줄, option 4개의 skeleton이다. 불러오기 오류는 error
StatePanel과 `다시 불러오기`, 저장 실패는 입력을 그대로 둔 채 bar 바로 위 error panel과
`다시 시도`를 제공한다. 저장 성공은 `답변이 나만 보기로 저장됐어요.`를 알린 뒤 다음 질문으로
이동하며 마지막 질문이면 나로 이동한다.

### 3. 변화

#### 정보 구조

1. `ScreenHeader`: `변화는 기록이 된다`
2. 설명: `달라진 문장을 보여드릴게요. 그 의미는 오직 내가 정해요.`
3. 기록별 변화 group
4. group 안 날짜 → `이전에는`/`지금은` → 답변 → 선택적 변화 이유·다음 시도

group 간격은 32pt, event padding은 20pt, 답변은 24/36이다. 날짜 rail과 본문은 기본에서
12pt 간격의 row, `fontScale >= 1.5`에서 column이다. 화살표, 상승·하락 색, 좋아짐·나빠짐과
성장 score는 없다. card 전체가 아니라 각 기록 제목과 답변 묶음이 상세 진입 button이 된다.

빈 상태는 `아직 비교할 과거 문장이 없어요. 지금의 답은 그대로 잘 보관하고 있어요.`와
`현재 기록 살펴보기`다. 로딩은 실제 group과 같은 skeleton 2개, 오류는 error StatePanel과
재시도다. 600자 답변과 1,200자 변화 이유도 잘리지 않으며 목록에서 긴 부가 맥락은 네 줄 후
`이어 읽기`, 확대에서는 전체 표시한다.

### 4. 공개 선택

#### 정보 구조

1. `ScreenHeader`: `보여줄 나 고르기`
2. 고정 설명: `이름과 한 줄 소개는 기본으로 보여요. 아래 기록만 하나씩 공개하거나 숨길 수 있어요.`
3. 기록별 `SceneCard`와 52pt 공개 상태 control
4. `BottomActionBar`: `공개 모습 미리보기`

상태 control은 자물쇠+`나만 보기`, 눈+`공개`를 사용한다. 공개로 바꾸면 `BlockingDialog`에서
현재 문장과 `과거 기록, 변화 이유와 작성 맥락은 공개되지 않아요.`를 확인한 뒤 미리보기로
이동한다. 이 시점에는 아직 공개하지 않는다. 공개 해제도 현재 문장을 확인하고 `방문자
화면에서 바로 사라지고 내 기록은 남아요.`를 알린다.

빈 상태는 `아직 고를 기록이 없어요`, `먼저 질문 하나를 만나 지금의 나를 남겨보세요.`,
`질문 만나기`다. 로딩은 SceneCard skeleton 3개, 초기 오류는 error StatePanel이다. 항목 변경
실패는 해당 card 아래 inline error를 표시하고 다른 card의 상태를 되돌리지 않는다.

### 5. 공개 미리보기

#### 정보 구조

1. profile renderer 밖 preview banner
2. 공개 profile cover: 이름과 선택적 intro
3. 공개 `SceneCard`만 있는 목록 또는 공개 항목 없음 StatePanel
4. Scene M 단색형과 `it’sME` footer 한 번
5. `BottomActionBar`: `이대로 공개하기`, `선택으로 돌아가기`

banner 문구는 `미리보기 중`, `다른 사람에게도 아래 모습 그대로 보여요.`다. 미리보기에만
banner와 action bar가 있고 profile renderer 내부에는 편집·공개 control이 없다.

공개 미리보기에서 공개 기록이 없으면 banner 아래에 `이름과 한 줄 소개만 보여요. 공개한
기록은 아직 없어요.`를 안내한다. 방문자와 공유하는 profile renderer의 빈 StatePanel 제목은
`공개한 기록은 아직 없어요.`다. 이름과 intro는 그대로 보이고, 비공개 범주, 수와 자리표시는
만들지 않는다. 공개 cover는 최소 280pt·radius 24pt, 공개 SceneCard는 최소 144pt다.

로딩은 방문자 renderer와 같은 cover·card skeleton, 오류는 profile 위치의 error StatePanel과
재시도다. 최종 공개 실패 시 미리보기와 선택 내용을 유지한다. 최종 공개 성공은 접근성 알림
후 공개 선택으로 돌아가 해당 card 상태만 갱신한다.

### 6. 기록 상세

#### 정보 구조

1. `ScreenHeader`: back `지금의 나로`, 범주와 기록 제목
2. 현재 답 SceneCard와 공개 상태·날짜
3. 선택적 `이 답을 남긴 이유`
4. `지금의 답으로 새로 남기기`, `공개 범위 살펴보기`
5. 지나온 기록: 최신부터 날짜·답·선택적 변화 이유·다음 시도
6. 조용한 파괴 행동 `이 기록 삭제하기`

편집 모드는 현재 답 600자, 변화 이유 1,200자, 다음 시도 600자다. 모두 label, 선택 여부,
counter와 오류를 연결하고 원문을 유지한다. 저장하면 과거 버전을 덮어쓰지 않는다. 공개 중인
기록을 수정하면 `새 문장은 나만 보기로 돌아왔어요. 공개 전에 실제 모습을 다시 확인해 주세요.`
를 알리고 공개 선택으로 이동하는 행동을 제공한다.

삭제는 `BlockingDialog`에서 현재 문장을 보여주고 `현재 문장과 과거 버전이 모두 영구 삭제되며
복구할 수 없어요. 공개 중이라면 방문자 화면에서도 바로 내려가요.`를 사용한다. 취소가 첫
행동, `영구 삭제하기`가 마지막 danger 행동이다.

로딩은 header와 현재 SceneCard, history 2개의 skeleton이다. 찾을 수 없음은 `이 기록을 찾지
못했어요.`, 권한 없음은 `이 기록을 볼 수 없어요.`로 분리하고 둘 다 `지금의 나로 돌아가기`를
제공한다. 저장·삭제 실패 시 dialog와 입력을 유지하고 화면에서 기록을 먼저 제거하지 않는다.

| --- | --- | --- |
| 정상 | 사용자 문장 우선, 하나의 주요 행동 | heading 하나, 논리적 읽기 순서 |
| 빈 상태 | 결핍 표현 없이 다음 선택 한 개 | 상태 제목부터 읽고 행동으로 이동 |

| 갱신 오류 | 기존 콘텐츠 유지, 인접 error | 입력·선택 보존, 오류로 포커스 이동하지 않음 |

## 인터랙션과 모션

- 화면 진입: 제목과 첫 콘텐츠를 함께 `opacity 0→1`, `translateY 6→0`, 180ms ease-out.
- option 선택: 배경·경계·체크·`선택됨`을 140ms ease-out에 함께 갱신한다.
- SceneCard 저장: 제자리에서 opacity 0→1, 220ms. 목록 전체를 밀어내는 spring은 사용하지 않는다.
- 공개 상태 변경: 해당 label과 preview 데이터만 180ms에 갱신한다.
- BlockingDialog: scrim 180ms, surface opacity와 scale `0.98→1` 180ms. bounce는 없다.
- skeleton은 정적이며 shimmer를 반복하지 않는다. 장식용 무한 반복, parallax, 자동 스크롤,
  진동 배경을 사용하지 않는다.
- 축소 모션에서는 이동·scale·순차 노출을 제거하고 즉시 변경 또는 100ms 이하 opacity만 쓴다.
- 저장, 삭제와 공개 성공은 시각 모션과 별개로 접근성 알림을 한 번 제공한다.

## 접근성 요구사항

- 모든 control은 44×44pt 이상이며 탭, 아이콘과 text label을 하나의 접근성 요소로 묶는다.
- 일반 텍스트 4.5:1, 큰 텍스트·아이콘·의미 있는 경계·focus 3:1을 측정한다.
- 색을 제거해도 선택, 공개 상태, 현재 버전, 오류와 활성 탭을 구분할 수 있다.
- focus는 3pt `color.focus`, 2pt 바깥 offset이며 component 크기를 바꾸지 않는다.
- 200%에서 가로 스크롤, fixed text height, 핵심 말줄임과 겹침이 없다.
- 스크린리더로 질문 저장, 기록 수정, 삭제 취소, 공개 미리보기와 공개 취소를 완료한다.
- `BlockingDialog`는 modal semantics, focus trap, escape 취소와 focus restore를 제공한다.
- 키보드가 열린 동안 입력, counter, 오류와 저장·건너뛰기까지 순서대로 접근할 수 있다.
- Scene M은 장식이면 접근성 트리에서 제외하고, 브랜드 식별이면 `it'sME` 한 번만 읽는다.

- [ ] Product Designer와 Reviewer가 개인정보, 접근성, 브랜드와 제품 철학을 각각 승인한다.

## 완료 정의

스프린트는 위 checklist가 모두 충족되고 `design-quality-gate.md`의 필수 캡처 묶음이 같은
commit으로 제출됐을 때 완료다. 기능 테스트 통과만으로 디자인 완료를 선언하지 않는다.
공용 token이나 primitive, 공개 renderer, 폰트, safe area가 바뀌면 관련 화면의 디자인 승인은
만료되고 다시 검증한다.
