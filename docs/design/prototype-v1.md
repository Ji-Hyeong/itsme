# 첫 프로토타입 디자인 명세

## 시각 방향: 나의 장면

잇츠미는 완성된 프로필을 전시하는 SNS가 아니라, 계속 달라지는 현재의 나를 짧은 문장으로
만나고 보존하는 공간이다. 화면은 `나의 장면`을 핵심 은유로 사용한다. 각 답은 카드 수나
완성도를 채우는 데이터가 아니라 지금의 나를 보여주는 하나의 장면이며, 여러 시기의 장면이
겹쳐 살아 있는 자기소개가 된다.

형광색과 굵은 검정 구조선으로 정보를 분할하는 `LIVE INDEX` 방향은 폐기한다. 과장된 영문
레이블, 신호·인덱스 번호와 기록 수 지표 대신 현대적인 한글 산세리프, 클라우드 그레이와
화이트의 넓은 여백, 절제된 인디고·세이지·살구, 부드럽게 구분되는 둥근 모듈을 사용한다.

## 경험 원칙

- 첫 화면은 기록이 없어도 제목, 여백과 한 개의 행동으로 완성된 장면이어야 한다.
- 프로필 사진, 팔로워, 좋아요, 조회수, 통계, 게시물 격자와 완성도 표시를 사용하지 않는다.
- 현재 답변은 크게, 설명과 조작은 작고 명료하게 배치해 사용자의 말이 UI보다 먼저 보이게 한다.
- 저장, 변경과 공개는 서로 다른 행동으로 인식되도록 화면과 피드백을 분리한다.
- 둥근 모듈은 내용을 묶는 데만 사용하고 같은 크기의 카드를 반복하는 대시보드는 만들지 않는다.
- 사진, 장문이나 꾸미기 설정이 없어도 색, 활자와 여백만으로 개인 화면이 완성되어야 한다.

## 정보 구조와 내비게이션

- `나`: 범주별 현재 문장과 최근 변화의 단서를 읽는 현재 상태
- `질문`: 한 번에 하나씩 만나는 자기 탐색 질문
- `변화`: 과거 답변, 변화 이유와 다음 시도
- `공개`: 공개 항목 선택, 방문자와 동일한 결과 미리보기

현재 구현된 네 탭의 수와 순서는 유지한다. 기존 `발견` 레이블만 행동이 명확한 `질문`으로
변경한다. 공개를 별도 탭으로 유지하되 공개 수나 공유 성과를 강조하지 않는다.

모바일에서는 화면 아래에 안전 영역을 포함한 내비게이션을 고정한다. 각 탭은 아이콘과 한글
레이블을 함께 제공하고 활성 상태는 글자 굵기, 아이콘 형태와 3px 인디고 표식으로 구분한다.
네 탭은 각각 내비게이션 유효 폭의 정확히 25%를 차지하고 최소 44×44pt 터치 영역을 갖는다.
내비게이션 콘텐츠 높이는 64px이며 기기의 bottom safe area를 그 아래에 더한다.
떠 있는 중앙 작성 버튼, 형광색 전체 반전과 선택 탭 전체를 채우는 큰 색상 카드는 사용하지
않는다.

프로토타입은 모바일 전용이다. 네이티브 앱은 360px, 390px와 430px 너비를 기준으로 검증하고,
Web은 모바일 확인용 preview로만 제공한다. Web 본문은 최대 480px로 중앙 정렬하며 데스크톱
내비게이션, 다열 레이아웃과 전용 기능을 만들지 않는다.

## 시각 시스템

### 색

- Cloud `#F4F5F7`: 앱 기본 바탕
- Surface `#FFFFFF`: 장면, 입력과 공개 프로필 표면
- Ink `#24262B`: 제목과 본문
- Muted `#666B73`: 보조 설명
- Line `#DDE0E5`: 구분선과 비활성 외곽선
- Indigo `#4457A6`: 주요 행동, 활성 탭과 키보드 포커스
- Indigo Soft `#EEF0FA`: 선택된 항목의 낮은 강조
- Sage `#718477`, Sage Soft `#EDF2EE`: 취향·배움 등 범주 단서
- Apricot `#C87D5B`, Apricot Soft `#FAEFEA`: 변화 시점과 따뜻한 강조
- Error `#B3261E`, Error Soft `#FCEDEA`: 오류 전용

인디고·세이지·살구는 화면 면적의 약 10% 안에서 사용한다. 큰 배경 전체나 여러 모듈을
서로 다른 강한 색으로 채우지 않는다. 색은 의미를 독점하지 않으며 활성 상태에는 아이콘과
텍스트 굵기, 공개 상태에는 자물쇠·눈 아이콘과 `나만 보기`·`공개` 레이블을 함께 제공한다.
Cloud 배경은 평평한 단색으로 유지하며 화면 모서리의 파스텔 glow, 큰 흐림 원과 배경 그라데이션을
사용하지 않는다.

### 타이포그래피

표시, 본문과 UI 모두 현대적인 한글 산세리프 계열을 사용한다. 구현 시 한 가족 안에서
굵기 범위를 충분히 제공하고 iOS·Android·Web에서 같은 한글 자폭과 줄바꿈을 검증한다.
후보는 `Pretendard Variable` 또는 `SUIT Variable`이며 실제 도입은 번들 크기와 라이선스를
프론트엔드가 확인한 뒤 확정한다.

- Screen title: 28px/38px, 700
- Hero and profile name: 32px/42px, 700
- Section title: 22px/31px, 700
- Scene answer: 24px/36px, 700
- Body: 16px/26px, 400
- Meta: 12px/18px, 500
- Control label: 15px/22px, 600
- 제목 자간은 `-0.02em` 이내, 본문 자간은 기본값을 유지한다.
- 영문 대문자 워드마크와 넓은 자간을 정보 위계나 상태 표현에 사용하지 않는다.

### 형태와 공간

4px 단위 공간 체계를 사용하되 주요 간격은 4, 8, 12, 16, 20, 24, 32, 40, 48px이다.
모든 지원 너비에서 콘텐츠 gutter는 20px이다. 기본 control 높이는 52px, 질문 option 높이는
60px이다. control radius는 14px, 장면·상태 카드 radius는 18px, 프로필 cover radius는
24px이며 작은 상태 레이블에만 999px pill을 허용한다.

화면의 버튼, 입력, option, 장면 카드와 상태 카드는 기본적으로 콘텐츠 영역의 `width: 100%`를
사용한다. 390px 화면에서는 화면 폭 390px, 좌우 gutter를 제외한 콘텐츠와 control 폭 350px가
하나의 공통 정렬선이 된다. 내용에 따른 축소 폭 버튼은 아이콘 전용 보조 행동에만 허용한다.

모듈은 1px `Line` 경계 또는 배경 차이 중 하나로만 구분한다. 그림자는 사용하지 않는다.
반복되는 색상 밴드, 2–4px 검정 테두리, 종이 그리드, 장식용 형광 블록과 파스텔 glow는
사용하지 않는다.

## 장면 모듈

답이 있는 범주만 주요 장면으로 표시한다. 각 장면은 범주명, 현재 답변, 공개 상태와 마지막
변경일을 포함한다. 답이 없는 범주는 동일한 크기의 빈 모듈로 반복하지 않고 화면 끝의
`더 알아보고 싶은 나` 영역에서 질문 진입 링크로 제공한다.

장면 전체는 기록 상세로 이동하는 하나의 터치 대상이다. 한 단어 답은 충분한 여백과 큰
활자로 보여주고, 긴 답은 모바일 목록에서 네 줄 뒤 `이어 읽기`를 제공한다. 200% 확대 또는
스크린리더 환경에서는 줄 수 제한을 제거한다. 범주별 색은 얇은 상단 표식이나 8px 점으로만
사용하고 장면 배경 전체를 채우지 않는다.

모든 기록은 동등한 기본 높이와 위계를 갖는다. 배열의 첫 기록을 크거나 높은 `featured`
장면으로 만들지 않으며, 저장 순서만으로 중요도를 부여하지 않는다.
모바일 장면의 기본 최소 높이는 168px, 내부 padding은 20px, 장면 사이 간격은 12px이다.

## 핵심 화면

### 빈 `나`

상단 제목은 `아직 말로 정하지 않은 나도 괜찮아요`, 설명은 `지금 답하기 편한 질문 하나부터
만나보세요.`를 사용한다. 아래에는 대표 질문 두세 개를 서로 다른 빈 카드가 아니라 하나의
둥근 안내 모듈 안에 간결하게 보여준다. 주요 행동은 `질문 하나 만나기`다. 기록 수, `0/6`,
인덱스 번호와 여섯 개의 빈 장면은 표시하지 않는다.

### 기록이 있는 `나`

제목은 `지금의 나`, 보조 문장은 사용자 intro 또는 `마음이 달라지면 언제든 다시 남길 수
있어요.`다. 답이 있는 장면을 우선 배치하고 각 장면의 현재 문장을 가장 크게 보여준다.
나만 보기 항목은 잠금 아이콘과 레이블을 함께 표시한다. 최근 변화가 있으면 장면 사이가
아닌 화면 하단에 `최근 달라진 문장`으로 최대 두 개만 제공한다.

프로필 cover는 콘텐츠 폭 100%, 390px 기준 350×280px, radius 24px와 padding 24px을 사용한다.
이름은 32px/42px이며 초기 avatar를 사용할 경우 52×52px을 넘지 않는다. cover 뒤 첫 섹션은
32px 간격으로 시작한다. 큰 파스텔 원과 avatar·badge가 동시에 경쟁하는 구성을 사용하지 않는다.

### 질문

상단에는 `취향에 관한 질문`처럼 범주를 한국어로 표시하고 질문 한 문장을 32px/42px로
보여준다. `01 / 06`, 진행 막대, `CHAPTER`, `SELECTED`는 사용하지 않는다. 선택지는 높이
60px의 둥근 행으로 제공하고 선택 시 Indigo Soft 배경, 체크 아이콘과 `선택됨` 상태를
함께 표시한다.

선택형 질문에는 `내 말로 쓰기`, 자유 입력에는 최대 600자와 현재 글자 수를 제공한다.
선택 후에만 `조금 더 남기고 싶다면` 맥락 입력을 점진적으로 연다. 주요 버튼은
`나만 보기로 남기기`, 보조 행동은 `지금은 건너뛸게요`다. 저장 실패 시 입력을 유지한다.
질문, 안내, option, 입력과 CTA는 모두 같은 콘텐츠 폭 100%를 사용한다. 주요 CTA 영역은
하단 네 탭 바로 위에 고정하고 화면 좌우 20px gutter 안에서 52px 높이 버튼을 제공한다.

### 변화

날짜별로 구분된 세로 흐름을 사용한다. 이전 문장과 현재 문장을 별도 모듈로 구분하고 화살표
대신 `이전에는`, `지금은`이라는 한글 레이블을 제공한다. 살구색은 날짜 점과 작은 강조에만
사용하며 좋음, 나쁨, 성장 또는 퇴보를 뜻하지 않는다. 변화 이유와 다음 시도는 사용자가
남긴 경우에만 노출한다. 과거 기록이 없으면 `아직 비교할 과거 문장이 없어요. 지금의 답은
그대로 잘 보관하고 있어요.`를 보여준다.

모바일 timeline event는 세로 카드 안에서도 날짜 rail과 본문이 나란한 row를 유지한다.
event padding은 20px, 답변은 24px/36px, 기록 그룹 사이 간격은 32px이다.

### 공개 선택

상단 제목은 `보여줄 나 고르기`, 설명은 `저장한 기록과 공개하는 기록은 달라요.`다. 각 장면에
`나만 보기` 또는 `공개` 상태를 텍스트와 아이콘으로 표시한다. 공개로 바꾸기 전에 추가될
현재 문장을 확인하고, 과거 기록과 작성 맥락은 공개되지 않는다고 안내한다.

하단의 `공개 모습 미리보기`는 방문자와 같은 공개 응답과 렌더러를 사용한다. 공개 항목 수는
버튼 강조, 배지, 성과 요약으로 표시하지 않는다.

공개 항목 카드는 폭 100%의 단일 열이며 범주 표식은 상단 4px 또는 작은 점으로만 제공한다.
공개 상태 control은 카드 하단의 폭 100%, 높이 52px 행으로 제공한다. 확인 카드의 padding은
20px이고 CTA는 폭 100%를 사용한다.

### 공개 프로필과 미리보기

미리보기에는 실제 프로필 바깥에 `미리보기 중 · 다른 사람에게도 아래 모습 그대로 보여요`
배너와 종료 행동을 둔다. 실제 공개 프로필에는 이름, intro와 공개한 장면만 표시한다.
`PUBLIC INDEX`, `OPEN PROFILE`, `STORIES`와 항목 수 지표는 사용하지 않는다.

공개 항목이 없으면 이름과 함께 `아직 꺼내 보여준 이야기가 없어요.`를 보여준다. 비공개
항목을 유추할 수 있는 빈 범주, 개수, 과거 날짜와 자리표시는 렌더링하지 않는다.

공개 프로필 cover는 폭 100%, 390px 기준 높이 280px와 radius 24px을 사용한다. 앱 로고는
공개 화면 footer에 한 번만 표시하며 외부 header, cover와 footer에 반복하지 않는다. 공개
장면의 최소 높이는 144px, 답변은 24px/36px이다.

## 상태 명세

- 로딩: 최종 장면과 같은 높이의 중립색 skeleton을 사용하고 사용자 데이터처럼 보이는
  임시 문구는 표시하지 않는다.
- 불러오기 오류: 원래 콘텐츠 위치에 설명, `다시 불러오기`와 오류 상태를 제공한다.
- 저장 중: 입력을 유지하고 버튼 레이블을 `남기는 중…`으로 바꾸며 중복 제출을 막는다.
- 저장 실패: 입력을 보존하고 오류 설명과 `다시 시도`를 같은 위치에 제공한다.
- 권한 없음: 데이터 영역을 비우고 `이 기록을 볼 수 없어요.`와 안전한 이탈 행동을 제공한다.
- 삭제: 삭제 대상의 현재 문장을 확인하고 복구 가능 여부를 설명한다. 실패 시 화면에서 먼저
  제거하지 않는다.
- 긴 콘텐츠: 목록 네 줄 접기와 `이어 읽기`, 상세 전체 표시를 사용한다.
- 공개 항목 없음: 결함이나 미완성으로 표현하지 않고 공유 가능한 정상 화면으로 유지한다.

## 모션과 피드백

- 화면 진입: 제목과 첫 장면을 180ms opacity와 6px 이하 이동으로 함께 노출한다.
- 질문 선택: 140ms 안에 배경, 체크 아이콘과 상태 레이블을 갱신한다.
- 저장 성공: 새 장면이 220ms 안에 제자리에서 나타나며 접근성 알림으로 저장 결과를 알린다.
- 공개 범위 변경: 해당 레이블과 미리보기만 180ms 안에 갱신하고 화면 전체를 전환하지 않는다.
- `prefers-reduced-motion`에서는 위치·크기 변화와 순차 노출을 제거하고 100ms 이하 opacity
  전환 또는 즉시 상태 변경만 사용한다.
- 장식 목적의 무한 반복, parallax, 진동하는 배경과 자동 스크롤을 사용하지 않는다.

## 모바일 화면 기준

- 360px: 콘텐츠 폭 320px, 20px gutter, 단일 열과 고정 하단 네 탭을 유지한다.
- 390px: 콘텐츠 폭 350px를 기본 설계 기준으로 사용한다.
- 430px: 콘텐츠 폭 390px를 유지하고 다열로 전환하지 않는다.
- Web preview: viewport가 넓어도 앱 프레임과 본문을 최대 480px로 중앙 정렬한다.
- 네이티브와 Web preview 모두 동일한 하단 네 탭과 정보 순서를 사용한다.
- 버튼, 입력, option과 카드는 모두 콘텐츠 폭의 100%이며 임의의 화면별 max width를 두지 않는다.
- 200% 글자 확대 또는 1.5 이상 font scale에서는 모든 모듈을 자연 높이 단일 열로 전환하고
  메타 정보를 답변 아래에 쌓는다. 사용자 텍스트에 absolute position을 사용하지 않는다.

## 접근성

- 일반 텍스트 대비 4.5:1, 큰 텍스트와 구조선·포커스 표시 대비 3:1 이상을 유지한다.
- 터치 대상은 최소 44×44pt이며 하단 탭과 주요 행동은 safe area를 포함한다.
- 각 장면은 `카테고리, 현재 답변, 공개 상태, 마지막 변경일` 순서의 접근성 이름을 갖는다.
- 장면 추가, 저장 완료, 공개 범위 변경과 오류를 접근성 live region으로 알린다.
- 질문, 도움말, 입력, 글자 수와 오류 메시지를 프로그램적으로 연결한다.
- 키보드 포커스는 3px Indigo outline과 2px 이상의 offset으로 항상 보이게 한다.
- 200% 확대에서 가로 스크롤 없이 읽고 조작할 수 있으며 논리적 읽기 순서는 시각 순서와 같다.
- 스크린리더, 키보드, 고대비, 축소 모션과 iOS·Android safe area를 출시 전 직접 검증한다.

## 프론트엔드 acceptance checklist

- 네 탭이 `나`, `질문`, `변화`, `공개` 순서와 동일한 한국어 레이블로 표시된다.
- 하단 네 탭이 각각 유효 폭의 25%를 차지하고 안전 영역을 포함한다.
- 화면에 `LIVE INDEX`, `SIGNAL`, `SELECTED`, `PRIVATE`, `PUBLIC`, `STORIES`가 노출되지 않는다.
- 형광 라임, 코발트와 주홍색이 큰 배경 면적으로 사용되지 않는다.
- Cloud 배경에 파스텔 glow, 큰 장식 원과 그라데이션이 표시되지 않는다.
- 기록이 한 개뿐이어도 여섯 개의 빈 슬롯이나 완성률 없이 완성된 화면처럼 보인다.
- 첫 기록이 크기나 높이로 강조되지 않고 다른 기록과 같은 위계를 갖는다.
- 질문은 진행률 없이 저장, 건너뛰기, 닫기와 나중에 수정을 지원한다.
- 모든 버튼과 카드가 콘텐츠 영역의 100% 폭을 사용하고 control 52px, option 60px 기준을 따른다.
- 새 기록은 `나만 보기`로 저장되고 저장 행동 가까이에 해당 사실이 표시된다.
- 공개 전환 전에 실제 공개될 현재 문장과 제외되는 정보를 확인할 수 있다.
- 미리보기와 방문자 화면이 동일한 공개 응답과 렌더러를 사용한다.
- 공개 프로필에 비공개 답변, 빈 자리표시, 과거 버전과 작성 맥락이 나타나지 않는다.
- 로딩, 오류, 저장 실패, 권한 없음, 삭제와 긴 콘텐츠 상태가 명세대로 제공된다.
- 360px, 390px, 430px와 최대 480px Web preview에서 정보 순서와 단일 열이 유지된다.
- 200% 확대, 키보드, 스크린리더와 축소 모션으로 핵심 여정을 완료할 수 있다.
