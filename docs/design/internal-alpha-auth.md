# 내부 알파 인증·세션·공개 공유 UX 명세

이 문서는 첫 프로토타입에 실제 계정과 영구 저장을 연결하는 내부 알파의 인증, 세션, 오류,
로그아웃, 공개 링크 공유와 기록 삭제 경험을 정의한다. 기존 화면의 시각·상호작용 기준은
`prototype-v1.md`를 따르며, 여기서는 계정이 생기면서 추가되는 상태와 전이를 보완한다.

내부 알파의 목적은 사용자를 오래 머물게 하거나 프로필 입력을 늘리는 것이 아니다. 사용자가
자신의 기록이 어느 계정에 안전하게 보존되는지 이해하고, 공개할 내용만 직접 고른 뒤 실제
방문자 화면을 확인하고 공유할 수 있게 하는 것이다.

## 범위와 전제

- 내부 알파의 UX 기준 인증 수단은 운영자가 발급한 `이메일 + 비밀번호`다. 자가 가입,
  이메일 인증과 비밀번호 재설정은 내부 알파 범위가 아니다.
- 운영자는 표시 이름과 공개 slug를 계정과 함께 미리 발급한다. 사용자는 로그인 화면에서
  표시 이름, slug, 성격, 취향과 사진을 입력하지 않는다.
- 공개 프로필 경로는 로그인 없이 열 수 있다. `나`, `질문`, `변화`, `공개 설정`, `계정`은
  소유자 세션이 필요하다.
- 새 기록은 항상 `나만 보기`로 저장한다. 계정 발급이나 첫 기록 저장을 공개 동의로 간주하지 않는다.
- 공개 링크에는 사용자 답변, 이메일, 세션 값과 분석용 식별자를 넣지 않는다. 방문자는 공개
  응답에 포함된 이름, 소개와 현재 공개 장면만 볼 수 있다.
- 계정 삭제는 개별 기록 삭제와 별도 정책이다. 내부 알파에는 셀프서비스 계정 삭제가 없고,
  본인 확인을 거친 운영 요청만 가능하다. 이 문서는 앱 안의 개별 기록 삭제만 확정한다.

## 사용자 흐름

### 1. 계정 발급과 첫 진입

**목적:** 내부 알파가 초대된 테스터를 위한 공간임을 이해하고, 앱에서 자기소개 입력을
요구받지 않은 채 발급받은 계정으로 로그인한다.

**진입:** 초대 안내의 앱 링크, 로그아웃 상태의 시작 화면.

**흐름:**

`초대·계정 발급 → 시작 → 로그인 → 빈 나 화면 또는 저장된 나 화면`

- 시작 화면 제목은 `내 기록으로 돌아가기`, 설명은 `초대받은 내부 테스트 계정으로 로그인해
  주세요.`다. 주요 행동은 로그인 폼의 `로그인`이다.
- 자가 가입 폼과 `처음이에요` 행동을 노출하지 않는다. 계정을 받지 못한 사용자를 위해
  `계정을 받지 못했나요?`를 보조 도움말로 제공하고, 초대 안내에 명시된 운영 채널로만 연결한다.
- 계정 발급 안내는 테스트 접근을 설명할 뿐 성격, 취향, 사진과 공개할 이야기를 미리 요구하지
  않는다. 로그인 뒤 기록이 없다면 기존의 온전한 빈 `나`와 `질문 하나 만나기`를 보여준다.
- 알파 대상이 아닌 사용자가 로그인 경로에 접근해도 공개 프로필 탐색이나 가입을 권하지 않는다.
  `내부 테스트는 초대받은 계정으로 이용할 수 있어요.`와 안전한 브라우저 뒤로가기를 제공한다.

**이탈:** 로그인 성공, 초대 안내의 지원 경로, 앱 또는 브라우저 닫기. 앱 안에서 자가 가입으로
이동하는 경로는 없다.

### 2. 로그인

**목적:** 기존 기록이 있는 계정으로 돌아온다는 사실과 실패 이유를 명확히 전달한다.

**진입:** 시작 화면, 보호 화면 접근 후 인증 필요, 세션 만료 후 `다시 로그인`.

**흐름:**

`로그인 → 세션 발급 → 원래 가려던 보호 화면 또는 나 화면`

- 이메일과 비밀번호만 요구한다. 이메일 키보드, 자동 대문자 해제, 비밀번호 표시 전환을 제공한다.
- `로그인`이 유일한 주요 행동이고 `로그인 정보를 잊었어요`는 보조 지원 행동이다. 공개
  프로필에는 로그인 유도를 두지 않으며, 별도 로그인 진입 후에도 방문 중이던 공개 경로를
  계정 소유자 화면으로 오인해 복원하지 않는다.
- 인증 실패는 `이메일이나 비밀번호를 다시 확인해 주세요.`로 표현한다. 어느 값이 계정에
  등록됐는지는 구분해 알려주지 않는다.
- 세션 만료 뒤 재로그인한 경우 원래 보호 화면과 입력 상태로 돌아가되, 저장·삭제·공개 변경
  요청을 자동 재전송하지 않는다. 사용자가 결과를 확인하고 다시 행동해야 한다.

**이탈:** 로그인 성공, 지원 안내, 시작 화면 복귀. 보호 화면에서 왔다면 성공 후 검증된 내부
경로만 복원하며 외부 URL이나 임의 경로를 그대로 실행하지 않는다.

### 3. 앱 시작과 세션 복원

**목적:** 개인 데이터가 잠깐 보였다가 사라지는 현상 없이 기존 세션의 상태를 확인한다.

**진입:** 앱 시작, Web의 보호 경로 직접 진입, 앱이 백그라운드에서 오래 머문 뒤 복귀.

**흐름:**

`앱 시작 → 세션 확인 → 유효하면 나 화면 / 세션 없음·무효면 시작 화면 / 네트워크 실패면 복원 오류`

- 확인 중에는 Cloud 배경 중앙에 단색 Scene M과 `내 기록을 불러오는 중…`만 보여준다. 개인
  데이터 skeleton, 이전 사용자의 이름과 하단 탭은 세션 확인 전 표시하지 않는다.
- 네트워크 실패를 로그아웃으로 처리하지 않는다. `연결을 확인한 뒤 다시 불러와 주세요.`와
  `다시 불러오기`, `로그인 화면으로`를 제공한다.
- 서버가 세션 무효를 명시한 경우에만 시작 화면으로 이동하고 `다시 로그인해 주세요.`를 한 번
  알린다. 사용자가 직접 로그아웃한 뒤에는 이 안내를 표시하지 않는다.
- 마지막 인증 활동 후 7일이 지나 만료된 경우 `오랫동안 로그인하지 않아 다시 확인이 필요해요.`를
  보조 설명으로 제공한다. 만료를 사용자의 잘못이나 기록 중단으로 표현하지 않는다.
- 공개 링크 직접 진입은 세션 복원을 기다리지 않는다. 공개 응답만 불러오며 소유자 세션 확인
  실패가 방문자 화면을 막지 않는다.

**이탈:** 세션 결과에 따라 보호 영역, 시작 화면 또는 공개 프로필로 이동. 복원 오류 화면은
사용자 행동 전까지 자동으로 반복 요청하거나 화면을 전환하지 않는다.

### 4. 인증 만료

**목적:** 진행 중인 기록을 잃지 않고, 실패한 행동이 완료된 것처럼 보이지 않게 한다.

**진입:** 보호 API가 인증 만료를 명시하거나, 앱 복귀 시 세션이 무효로 확인됨.

**흐름:**

`보호 행동 → 인증 만료 감지 → 만료 안내 → 재로그인 → 원래 화면 복귀 → 사용자 재시도`

- 작성·수정 중이면 현재 입력을 화면 상태에 유지하고 차단 대화상자를 띄운다. 문구는
  `로그인이 만료됐어요` / `작성한 내용은 이 화면에 그대로 있어요. 다시 로그인한 뒤 직접
  저장해 주세요.`다.
- 주요 행동은 `다시 로그인`, 보조 행동은 `나중에 나가기`다. 보조 행동은 입력이 사라질 수
  있음을 확인한 뒤 시작 화면으로 보낸다.
- 공개 범위 변경, 삭제처럼 되돌리기 어려운 행동은 성공 표시를 하지 않는다. 재로그인 뒤 서버의
  현재 상태를 다시 불러와 보여주고 사용자가 다시 선택하게 한다.
- 읽기 화면에서 만료되면 비공개 데이터를 즉시 빈 화면으로 덮지 않고 차단 레이어로 가린 뒤
  재로그인을 요청한다. 다른 계정으로 로그인했다면 이전 화면을 복원하지 않고 새 계정의 `나`로
  이동한다.
- 방문자 공개 화면에는 `로그인이 만료됐어요`를 노출하지 않는다. 공개 응답 오류로 별도 처리한다.

**이탈:** 같은 계정 재로그인 성공, 시작 화면 이동, 다른 계정 로그인 후 새 계정의 `나` 이동.

### 5. 로그아웃

**목적:** 현재 기기에서 개인 기록 접근을 종료하는 결과를 이해하고 선택한다.

**진입:** `나` 화면 상단의 `계정` → 계정 화면 → `로그아웃`.

**흐름:**

`계정 → 로그아웃 선택 → 확인 → 세션 종료 → 시작 화면`

- `계정`은 다섯 번째 탭이 아니라 `나`의 보조 경로다. 계정 화면은 현재 이메일과 로그아웃만
  우선 제공하며 프로필 완성도나 활동 통계를 추가하지 않는다.
- 확인 문구는 `이 기기에서 로그아웃할까요?` / `이 기기의 로그인만 끝나요. 남긴 기록과 공개
  링크, 다른 기기의 로그인은 그대로예요.`다.
  주요 행동은 `로그아웃`, 보조 행동은 `계속 머물기`다.
- 로그아웃 요청 중에는 버튼을 `로그아웃하는 중…`으로 바꾸고 중복 요청을 막는다. 성공 후
  보호 화면의 메모리와 캐시를 지우고 시작 화면으로 이동한다.
- 네트워크 오류가 있어 서버 세션 종료를 확인하지 못하면 성공처럼 이동하지 않는다. `로그아웃하지
  못했어요. 연결을 확인하고 다시 시도해 주세요.`와 `다시 시도`를 제공한다. 내부 알파는 서버에서
  현재 세션이 무효화된 것을 확인한 뒤에만 로그아웃 완료로 처리한다.

**이탈:** 확인 취소로 계정 화면 복귀, 성공으로 시작 화면 이동.

### 6. 공개 링크 미리보기와 공유

**목적:** 무엇이 보이는지 확인한 뒤 사용자가 선택한 채널로 링크를 전달한다.

**진입:** `공개` 탭 → `공개 모습 미리보기`.

**흐름:**

`공개 후보 선택 → 방문자 응답 모델 기반 미리보기 → 이대로 공개하기 → 공개 성공 확인 → 링크 공유 → 시스템 공유 시트 또는 링크 복사`

- `나만 보기` 항목의 선택은 공개 후보를 만드는 로컬 초안일 뿐 공개 범위를 바꾸지 않는다.
  선택 화면을 닫거나 네트워크 오류가 나도 현재 공개 URL에는 영향을 주지 않는다.
- 후보 미리보기는 서버가 공개 응답과 같은 필드로 투영한 결과와 공개 프로필 렌더러를 사용한다.
  소유자 응답을 Client에서 임의로 가려 미리보기로 만들지 않는다.
- 미리보기 상단의 앱 바깥 배너는 `미리보기 중` / `다른 사람에게도 아래 모습 그대로 보여요.`를
  제공한다. 공개 전 행동은 `이대로 공개하기`와 `다시 고르기`이며, `링크 공유`는 공개 성공
  응답과 최신 공개 URL 결과가 일치한 뒤에만 나타난다.
- 공개 요청 중에는 `공개하는 중…`으로 표시하고 후보 선택을 잠근다. 실패하면 현재 공개 상태는
  그대로 두고 `공개하지 못했어요. 고른 내용은 그대로 있어요.`와 `다시 시도`를 제공한다.
- 네이티브 `링크 공유`는 시스템 공유 시트를 연다. Web은 지원 시 Web Share를 사용하고,
  지원하지 않으면 링크를 클립보드에 복사한다. 성공 알림은 `공개 링크를 복사했어요.`다.
- 공유 메시지 기본문은 `지금의 저를 소개할게요.`와 공개 URL만 포함한다. 공개 장면의 원문,
  항목 수, 이메일, 변화 기록과 작성 맥락을 공유 메시지나 URL에 붙이지 않는다.
- 사용자가 시스템 공유 시트를 닫아도 실패 토스트를 띄우지 않는다. 공유 호출 자체가 실패했을
  때만 `공유 도구를 열지 못했어요. 링크를 복사해 주세요.`와 `링크 복사`를 제공한다.
- 공개 상태를 바꾼 직후에는 미리보기 응답을 새로 받아 최신 결과를 확인한 뒤 공유할 수 있다.
  로컬에서 낙관적으로 만든 미리보기로 링크를 공유하지 않는다.
- 공개 직전 `상대가 이미 저장하거나 촬영한 내용까지 거둘 수는 없어요.`를 설명한다. 불안을
  과장하지 않되 공개 해제와 삭제가 상대의 사본까지 회수한다는 인상을 주지 않는다.
- 공개 중인 기록을 수정하면 해당 장면은 즉시 `나만 보기`가 되고 기존·수정 원문 모두 공개
  응답에서 빠진다. 수정 완료 알림에 `수정한 내용은 나만 보기로 바뀌었어요.`를 포함하며,
  다시 공유하려면 최신 방문자 미리보기와 최종 공개 확인을 거친다.
- 이미 공개 중인 장면의 `나만 보기로 바꾸기`는 공개 후보 흐름과 분리한다. 확인 문구는
  `공개 링크에서 이 이야기를 숨길까요?` / `내 기록과 지난 문장은 그대로 남아요.`이며,
  `나만 보기로 바꾸기` 성공 직후 최신 공개 응답에서 사라져야 한다. 선택만 하고 적용하지 않은
  것처럼 모호하게 두지 않으며 실패하면 공개 상태를 그대로 표시한다.

**이탈:** 시스템 공유 완료·취소 후 미리보기 유지, `미리보기 닫기`로 공개 선택 복귀, 공개
프로필의 외부 방문자는 브라우저 뒤로가기로 원래 위치 복귀.

**방문자 로딩·오류:** 공개 프로필 로딩은 공개 cover와 장면 형태의 중립색 skeleton만 제공하고
소유자의 이전 데이터나 임시 이름을 쓰지 않는다. 네트워크 실패는 `지금은 공개 모습을 불러오지
못했어요.`와 `다시 불러오기`를 원래 콘텐츠 위치에 제공한다. 존재하지 않거나 사용할 수 없는
slug는 모두 `이 공개 페이지를 찾을 수 없어요.`와 `돌아가기`로 동일하게 표현해 계정·slug의
존재 여부를 더 설명하지 않는다. 공개 API의 인증 오류도 방문자에게 로그인을 요구하지 않는다.

### 7. 공개 항목 없음

**목적:** 공개하지 않기로 한 선택을 결함이나 미완성으로 표현하지 않는다.

**진입:** 공개 항목이 없는 상태의 공개 탭, 미리보기 또는 공개 링크.

- 소유자 공개 탭의 제목과 설명은 그대로 유지하고 상태 카드는 `아직 공개로 고른 이야기가
  없어요.` / `원할 때 한 장면씩 골라 보여줄 수 있어요.`를 사용한다.
- `공개 모습 미리보기`는 활성 상태로 제공한다. 미리보기와 실제 공개 링크는 이름과
  `아직 꺼내 보여준 이야기가 없어요.`만 표시하며 비공개 범주, 빈 슬롯, 기록 수와 과거 날짜를
  렌더링하지 않는다.
- 빈 공개 프로필도 정상 공개 응답이다. 오류 코드, 가입 유도, 프로필 완성 권유를 대신 보여주지
  않는다. 링크 공유도 가능하지만 강조하거나 반복 권유하지 않는다.
- 소유자에게만 `보여줄 나 고르기` 복귀 행동을 제공한다. 방문자에게는 소유자 전용 행동과
  로그인 유도를 제공하지 않는다.

### 8. 개별 기록 삭제

**목적:** 삭제 대상과 공개 영향, 복구 가능 여부를 이해한 뒤 명시적으로 확정한다.

**진입:** 기록 상세 → `이 기록 삭제하기`.

**흐름:**

`기록 상세 → 삭제 확인 → 삭제 요청 → 성공 시 나 화면 / 실패 시 상세 유지`

- 확인 화면은 bottom sheet보다 내용이 잘리지 않는 전체 높이 대화상자 또는 별도 화면을 우선한다.
  범주명과 현재 문장을 먼저 보여주며, 긴 문장은 네 줄로 자르지 않고 확인 영역 안에서 스크롤한다.
- 안내는 `이 기록과 지난 문장을 함께 영구 삭제해요. 공개 중이라면 공개 링크에서도 보이지
  않아요.`와 `내부 알파에서는 삭제한 기록을 되돌릴 수 없어요.`를 사용한다.
- 주요 파괴 행동은 `기록 삭제하기`, 보조 행동은 `그대로 둘게요`다. 기본 포커스는 보조 행동에
  두고, 입력 키보드의 Enter만으로 파괴 행동이 실행되지 않게 한다.
- 삭제 중에는 `삭제하는 중…`으로 표시하고 대화상자를 닫거나 중복 제출할 수 없게 한다. 성공
  후 `기록을 삭제했어요. 공개 링크에도 반영됐어요.`를 접근성 알림으로 전달한다.
- 실패하면 대화상자와 기록을 그대로 유지한다. 문구는 `기록을 삭제하지 못했어요. 내용은 그대로
  보관 중이에요.`이며 `다시 시도`와 `그대로 둘게요`를 제공한다.
- 인증 만료가 발생하면 삭제 성공을 추정하지 않는다. 재로그인 후 기록 존재 여부를 다시 확인하고,
  존재하면 사용자가 삭제를 다시 확정하게 한다.

**이탈:** 취소로 기록 상세, 성공으로 `나`, 실패 후 취소로 기록 상세.

## 화면별 정보 우선순위와 카피

| 화면·상태 | 가장 먼저 읽는 내용 | 주요 행동 | 보조 행동·도움말 |
| --- | --- | --- | --- |
| 시작·로그인 | `내 기록으로 돌아가기` | `로그인` | `초대받은 내부 테스트 계정으로 로그인해 주세요.` |
| 계정 없음 | `내부 테스트는 초대받은 계정으로 이용할 수 있어요.` | 없음 | `계정을 받지 못했나요?` |
| 세션 복원 | `내 기록을 불러오는 중…` | 없음 | 개인 데이터 표시 없음 |
| 복원 오류 | `지금은 기록을 불러오지 못했어요` | `다시 불러오기` | `로그인 화면으로` |
| 인증 만료 | `로그인이 만료됐어요` | `다시 로그인` | `작성한 내용은 이 화면에 그대로 있어요.` |
| 계정 | 현재 로그인 이메일 | `로그아웃` | 기록·공개 상태 요약을 표시하지 않음 |
| 공개 후보 미리보기 | `미리보기 중` | `이대로 공개하기` | `다시 고르기` |
| 공개 완료 미리보기 | `다른 사람에게도 아래 모습 그대로 보여요.` | `링크 공유` | `미리보기 닫기` |
| 공개 항목 없음 | `아직 꺼내 보여준 이야기가 없어요.` | 소유자만 `보여줄 나 고르기` | 방문자 행동 없음 |
| 삭제 확인 | 삭제할 현재 문장 | `기록 삭제하기` | `그대로 둘게요` |

필드 오류는 추상적인 `잘못된 값입니다` 대신 해결 방법을 말한다.

- 빈 이메일: `이메일을 입력해 주세요.`
- 이메일 형식: `이메일 형식을 다시 확인해 주세요.`
- 빈 비밀번호: `비밀번호를 입력해 주세요.`
- 요청 과다: `잠시 뒤 다시 시도해 주세요.`와 다시 가능한 정확한 시간이 있으면 함께 표시한다.
- 알 수 없는 서버 오류: `요청을 마치지 못했어요. 입력한 내용은 그대로 있어요.`

## 오류 표현 원칙

- 초기 화면 전체를 불러오지 못하면 콘텐츠 위치에 상태 화면을 제공한다. 일부 목록만 실패하면
  해당 섹션 안에서 오류와 재시도를 제공하고 정상 섹션을 숨기지 않는다.
- 인터넷 연결 오류와 인증 오류를 같은 문구로 처리하지 않는다. 네트워크 실패만으로 세션이나
  입력을 지우지 않는다.
- 저장, 공개 변경과 삭제는 서버 성공을 확인하기 전 완료 알림을 제공하지 않는다. 재시도 시
  동일 요청의 결과를 먼저 확인할 수 있도록 구현하되 사용자가 같은 기록을 두 번 만들게 하지 않는다.
- 오류 메시지는 Error 색만으로 구분하지 않는다. 오류 아이콘, `오류` 접근성 상태와 해결 행동을
  함께 제공한다.
- 짧은 일시 알림만으로 복구 행동을 전달하지 않는다. 토스트가 사라져도 원래 위치에 오류 설명과
  `다시 시도`가 남아 있어야 한다.
- 자유 서술, 이메일, 비밀번호와 공개 전 기록 원문을 오류 메시지, URL, 로그와 분석 이벤트에
  포함하지 않는다.

## 컴포넌트와 인터랙션

기존 `prototype-v1.md`의 색, 타이포그래피, 20px gutter, 52px control, 14px control radius와
18px 상태 카드 radius를 그대로 사용한다.

- `AuthScreen`: 로고를 한 번만 사용하고 제목, 설명, 폼, 주요 행동, 지원 행동 순으로
  구성한다. 모바일과 Web 모두 최대 480px 단일 열이다.
- `Field`: 보이는 레이블을 placeholder와 분리한다. 레이블, 입력, 도움말, 오류를 프로그램적으로
  연결하고 오류가 생겨도 레이아웃이 입력을 가리지 않는다.
- `PasswordField`: `비밀번호 보기`·`비밀번호 숨기기` 텍스트와 아이콘을 함께 사용하며 누르는
  동안만 보이는 방식이 아니라 명시적인 토글 상태를 제공한다.
- `InlineError`: 오류 제목, 설명과 복구 행동을 포함한다. 입력 오류는 해당 입력 바로 아래,
  요청 오류는 폼 또는 요청한 컴포넌트의 끝에 둔다.
- `BlockingDialog`: 인증 만료와 삭제 확인에 사용한다. 제목, 결과 설명, 주요·보조 행동 순서이며
  배경 콘텐츠는 스크린리더와 키보드 탐색에서 제외한다.
- `SessionGate`: 세션 확인 전 보호 화면을 렌더링하지 않는다. 공개 경로에는 적용하지 않는다.
- `ShareAction`: 결과 확인이 끝난 미리보기에서만 노출한다. 실행 중 `공유 준비 중…`으로 바꾸며
  여러 공유 시트를 동시에 열지 않는다.
- `AccountEntry`: `나` 화면 제목 가까이에 `계정` 텍스트 레이블로 제공한다. 아이콘 단독이면
  접근성 이름을 제공하더라도 200% 확대에서 의미가 약해지므로 텍스트를 우선한다.

입력 포커스 시 해당 필드가 키보드와 고정 CTA 사이에 완전히 보이도록 스크롤한다. 키보드가
열리면 CTA를 키보드 위에 억지로 고정해 입력을 가리지 말고, 폼 끝의 자연스러운 흐름 안에서
스크롤해 접근하게 한다. 제출 후 첫 오류 필드로 포커스를 이동하고 오류 요약을 먼저 알린다.

## 반응형과 긴 콘텐츠

- 360px, 390px, 430px에서 20px gutter와 단일 열을 유지한다. 인증 화면에는 하단 네 탭을
  표시하지 않고, 로그인 후 보호 영역에서만 네 탭을 제공한다.
- Web은 최대 480px 앱 프레임을 중앙 정렬한다. 공개 프로필 역시 공개 콘텐츠 순서를 바꾸거나
  데스크톱 전용 열, 소유자 로그인 패널을 추가하지 않는다.
- 200% 글자 확대 또는 font scale 1.5 이상에서는 제목, 설명, 필드, 행동을 한 열의 자연 높이로
  쌓는다. 주요·보조 버튼을 한 행에 두지 않고 각각 100% 폭으로 쌓는다.
- 이메일처럼 긴 계정 값은 컨테이너를 밀어내지 않게 줄바꿈한다. 사용자가 쓴 기록은 삭제 확인과
  공개 화면에서 단어 중간을 임의로 자르지 않으며, URL 등 긴 토큰은 안전하게 줄바꿈한다.
- 공개 프로필 장면은 기본 목록에서 네 줄 뒤 `이어 읽기`를 사용할 수 있으나 200% 확대와
  스크린리더에서는 줄 수 제한을 제거한다. 삭제 확인은 항상 전체 문장을 확인할 수 있어야 한다.
- 가로 방향과 작은 높이에서는 로고·장식을 줄이고 제목, 입력, 오류와 행동을 우선한다. 키보드가
  열린 상태에서도 제출과 취소 행동에 스크롤로 도달할 수 있어야 한다.

## 모션과 피드백

- 인증 화면 진입은 제목과 폼을 180ms opacity, 6px 이하 이동으로 함께 보여준다. 필드를
  순차적으로 튀어나오게 하지 않는다.
- 세션 복원 표시는 무한 회전만으로 상태를 전달하지 않고 `내 기록을 불러오는 중…` 문구를
  함께 제공한다.
- 대화상자는 160ms 이하 opacity와 scale 0.98→1 범위 안에서 나타난다. 축소 모션에서는
  위치·크기 변화를 제거하고 즉시 표시하거나 100ms 이하 opacity만 사용한다.
- 로그인, 로그아웃, 공유와 삭제 성공·실패는 시각적 상태와 접근성 live announcement를
  함께 제공한다. 성공 모션이 끝날 때까지 다음 화면 이동을 지연하지 않는다.
- 장식용 반복 모션, 인증 성공 축하 애니메이션, 공개 수 증가 애니메이션을 사용하지 않는다.

## 접근성 인수 기준

- 모든 입력은 보이는 레이블, 입력 목적, 도움말과 오류 연결을 갖는다. iOS·Android·Web의
  자동 완성 목적은 이메일과 현재 비밀번호를 정확히 구분한다.
- 키보드만으로 시작 → 로그인 → 첫 질문 → 공개 선택 → 미리보기 → 링크 복사 →
  로그아웃을 완료할 수 있다. 포커스가 대화상자 밖이나 가려진 하단 탭으로 빠지지 않는다.
- 대화상자가 열릴 때 제목으로 포커스를 이동하고, 닫으면 실행한 컨트롤로 돌려보낸다. 삭제 확인의
  초기 포커스는 `그대로 둘게요`, 인증 만료는 `다시 로그인`이다.
- 일반 텍스트 4.5:1, 큰 텍스트·입력 경계·포커스 표시 3:1 이상의 대비를 유지한다. 오류,
  선택, 공개와 비공개를 색만으로 표현하지 않는다.
- 모든 터치 대상은 최소 44×44pt다. 비밀번호 표시, 뒤로가기, 계정과 미리보기 닫기에도 동일하게
  적용한다.
- 입력 오류, 로그인 성공·실패, 세션 만료, 로그아웃, 공유 링크 복사와 삭제 결과를 중복되지
  않는 짧은 live announcement로 알린다. 사용자의 이메일이나 기록 원문은 읽지 않는다.
- 200% 글자 확대에서 가로 스크롤, 잘림, 겹침, 버튼 레이블 생략이 없고, 화면 순서와 접근성
  순서가 제목 → 설명 → 입력·상태 → 주요 행동 → 보조 행동으로 일치한다.
- 스크린리더가 공개 프로필을 읽을 때 비공개 범주 수, 자리표시자와 소유자 행동을 탐색할 수
  없어야 한다.
- 축소 모션에서 화면·대화상자 이동과 순차 등장 없이 모든 결과를 같은 시간 안에 이해할 수 있다.

## 프론트엔드 acceptance checklist

- [ ] 보호 화면은 세션 확인 전 개인 데이터와 하단 탭을 잠깐 노출하지 않는다.
- [ ] 공개 프로필 직접 진입은 소유자 세션 복원과 분리되며 로그인 없이 동작한다.
- [ ] 시작·로그인 화면은 초대 계정의 이메일과 비밀번호만 받으며 자가 가입, 표시 이름과 slug
  입력을 노출하지 않는다.
- [ ] 첫 기록 저장 뒤 공개 항목은 없으며 모든 새 기록은 `나만 보기`다.
- [ ] 로그인 실패와 네트워크 오류 후 입력값이 유지되고 중복 제출이 차단된다.
- [ ] 네트워크 실패는 로그아웃으로 처리되지 않으며 `다시 불러오기`가 같은 위치에 남는다.
- [ ] 인증 만료 후 작성 입력이 유지되고, 재로그인 뒤 실패한 저장·삭제·공개 변경을 자동
  재전송하지 않는다.
- [ ] 다른 계정으로 재로그인하면 이전 계정의 화면·입력·캐시를 복원하지 않는다.
- [ ] 로그아웃 확인은 기록과 공개 링크가 삭제되지 않는다는 결과를 설명한다.
- [ ] 로그아웃은 현재 기기 세션만 끝내며 서버 무효화를 확인하기 전 성공처럼 표시하지 않는다.
- [ ] 로그아웃 성공 후 뒤로가기로 보호 화면과 개인 데이터에 접근할 수 없다.
- [ ] `링크 공유`는 방문자 응답 기반 미리보기에서만 제공되고 공유 메시지에 기록 원문·항목 수·
  이메일이 포함되지 않는다.
- [ ] `나만 보기` 항목을 고르기만 해서는 공개되지 않으며 후보 미리보기의 `이대로 공개하기`
  성공 후에만 공개 응답에 나타난다.
- [ ] 공개 해제는 개인 기록과 과거 버전을 유지하고 서버 성공 직후 새 공개 응답에서 현재
  장면만 제거한다.
- [ ] 공유 시트 취소는 오류로 표시하지 않고, 호출 실패에는 `링크 복사` 대안을 제공한다.
- [ ] 공개 항목이 없어도 미리보기와 공개 링크가 정상 렌더링되며 비공개 범주를 유추할 빈 슬롯,
  수치와 날짜가 없다.
- [ ] 공개 중인 기록을 수정하면 즉시 `나만 보기`가 되고 최신 미리보기·최종 확인 전에는 다시
  공개되지 않는다.
- [ ] 삭제 확인에서 범주, 현재 문장, 지난 버전·공개 링크 영향과 복구할 수 없음을 확인할 수 있다.
- [ ] 삭제 실패·인증 만료 시 기록을 먼저 제거하지 않고 재시도 또는 안전한 이탈을 제공한다.
- [ ] 360px, 390px, 430px와 최대 480px Web에서 단일 열, 20px gutter와 100% 폭 control을 유지한다.
- [ ] 200% 확대에서 인증, 만료 복귀, 공유와 삭제 흐름을 가로 스크롤이나 잘림 없이 완료한다.
- [ ] 키보드와 스크린리더로 로그인부터 로그아웃까지 완료하고 모든 오류·성공 결과를
  인지할 수 있다.
- [ ] 일반 텍스트 4.5:1, 구조·포커스 3:1, 44×44pt 터치 영역과 축소 모션 대안을 충족한다.

## 계약·구현 영향

- Client는 공개 라우트와 보호 라우트의 초기 로딩을 분리하고, 세션 확인·유효·없음·네트워크
  실패·만료 상태를 서로 다른 화면 상태로 표현해야 한다.
- Client는 자가 가입 경로를 노출하지 않으며, 표시 이름과 slug는 운영자가 발급한 계정의
  읽기 정보로만 받는다. 계정 발급용 API가 필요해도 공개 Client 인증 흐름과 분리한다.
- 인증 API는 로그인, 세션 확인·갱신과 로그아웃의 오류를 네트워크 오류와 구분할 수 있는
  안정적인 오류 코드를 제공해야 한다. 비밀번호나 계정 존재 여부를 오류 응답에 노출하지 않는다.
- 세션 만료 설정은 내부 알파 정책인 마지막 인증 활동 후 7일과 일치해야 하며 로그아웃은 현재
  세션만 서버에서 즉시 무효화해야 한다.
- 재로그인 복귀에는 검증된 내부 return path와 같은 계정 여부 판단이 필요하다. 실패한 변경
  요청은 자동 재전송하지 않고 서버 상태를 다시 읽는다.
- 공개 링크는 방문자 전용 응답과 렌더러를 사용한다. 공개 항목이 0개인 응답도 정상 상태로
  계약하며 소유자 전용 필드, 비공개 범주와 과거 버전을 직렬화하지 않는다.
- 공개 후보 미리보기 API는 후보를 공개 응답과 같은 안전한 필드로 투영하되 실제 공개 범위를
  바꾸지 않아야 한다. 최종 공개 확인과 공개 해제는 각각 명시적 변경 요청으로 분리한다.
- 기록 삭제 응답은 현재 값, 모든 과거 버전, 맥락과 파생 공개 데이터의 영구 삭제 완료를
  계약으로 정의해야 한다. 성공 직후 새 소유자·공개 응답에 원문이 없어야 한다.
- Client 테스트 fixture에는 세션 복원 네트워크 실패, 인증 만료 중 작성, 다른 계정 재로그인,
  공유 취소·실패, 공개 0개와 삭제 실패 상태가 포함되어야 한다.

## PO·Backend 확정 필요 사항

아래 항목은 UX가 독단적으로 확정하지 않는다. 결정 전까지 화면을 추가하거나 모호한 약속을
노출하지 않는다.

- 초대 계정 발급·접근 회수·로그인 정보 분실을 안내할 운영 채널
- 정식 출시의 자가 가입, 이메일 인증, 비밀번호 조건과 재설정 수단
- 정식 출시의 공개 slug 변경·폐기, 링크 만료와 공유 캐시 정책
- 정식 출시의 법정 보존 대상, 삭제 유예, 백업 최대 삭제 기한과 계정 삭제 흐름
