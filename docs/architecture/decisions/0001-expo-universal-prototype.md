# ADR-001: Expo 유니버설 프로토타입

- 날짜: 2026-07-14
- 상태: 승인

## 맥락

잇츠미의 첫 구현은 모바일 앱다운 탐색 경험과 링크로 확인할 수 있는 공개 프로필을
동시에 검증해야 한다. 아직 Backend가 없으므로 화면은 실제 API와 같은 계약을 구현한
mock adapter로 동작해야 하며, 이후 실제 서버를 연결할 때 화면을 다시 작성하지 않아야 한다.

## 결정

- Expo, React Native, Expo Router와 TypeScript strict mode로 Android, iOS와 Web을 함께 지원한다.
- 앱 화면은 `ItsmeApi` port에만 의존하고 mock 구현을 직접 가져오지 않는다.
- 소유자 프로필과 공개 프로필 모델을 분리한다. 공개 미리보기와 방문자 화면은 같은
  `PublicProfile` 응답과 렌더러를 사용한다.
- 서버 상태 라이브러리와 영구 저장소는 실제 Backend 계약 및 민감 데이터 보존 정책이
  확정되기 전까지 도입하지 않는다. 프로토타입 상태는 메모리에만 둔다.
- 디자인 토큰과 React Native `StyleSheet`를 사용해 잇츠미 고유의 편집 노트 시각 언어를 만든다.

## 검토한 대안

### Vite 기반 React Web

빠른 브라우저 프로토타이핑에는 유리하지만 네이티브 앱으로 전환할 때 화면과 상호작용을
다시 검증할 가능성이 크다. 공개 프로필만 별도 Web으로 분리할 필요도 생긴다.

### 네이티브 iOS 우선

모바일 품질은 높지만 Android와 공개 프로필 Web 검증이 늦어지고 초기 반복 비용이 크다.

## 영향

- 하나의 코드베이스에서 모바일과 데스크톱 Web을 시각 검증할 수 있다.
- 네이티브와 Web의 접근성 차이는 플랫폼별 수동 검증이 필요하다.
- 실제 인증, 캐시와 오프라인 저장은 별도 ADR 없이는 추가하지 않는다.

## 되돌리기

도메인 계약과 데이터 port를 React Native UI에서 분리한다. 실제 사용자 검증에서 Web 또는
네이티브 전용 구현이 필요해지면 계약과 fixture를 유지한 채 화면 계층만 교체한다.
