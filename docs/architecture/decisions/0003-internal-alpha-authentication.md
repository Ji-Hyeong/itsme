# ADR-003: 내부 알파 초대 계정과 불투명 세션

- 날짜: 2026-07-22
- 상태: 승인

## 맥락

내부 알파는 실제 사용자별 기록을 서버에 영구 저장하고 공개 범위를 검증해야 하지만,
자가 가입·비밀번호 재설정·MFA와 계정 복구 정책은 아직 확정하지 않았다. 인증 구현이
비공개 자기 서술의 소유권 경계를 강제하면서도 정식 출시의 인증 제공자를 고정하지 않아야 한다.

## 결정

- 내부 알파 계정은 운영자가 발급하며 공개 가입 API와 가입 화면을 제공하지 않는다.
- 최초 초대 계정은 명시적으로 활성화한 bootstrap 설정으로만 생성한다. bootstrap 비밀번호는
  환경에서 주입하고 저장소·로그·오류 응답에 남기지 않으며 계정 생성 후 설정을 비활성화한다.
- 비밀번호는 BCrypt cost 12로 단방향 저장한다. 로그인 실패는 계정 존재 여부와 관계없이 같은
  검증 경로와 오류 형태를 사용한다.
- 로그인 성공 시 256-bit 암호학적 난수 토큰을 한 번만 반환하고, 서버에는 SHA-256 해시만 저장한다.
- 세션은 마지막 인증 활동부터 7일 뒤 만료하는 sliding expiration을 사용한다. 로그아웃은 현재
  토큰을 즉시 폐기하며 여러 기기의 세션은 서로 독립적으로 유지한다.
- Native Client는 토큰을 OS 보안 저장소에 보관한다. Web은 내부 미리보기 용도로만 사용하고
  브라우저 종료 범위의 저장소를 사용한다. Client bundle에 비밀값을 포함하지 않는다.
- 인증되지 않은 요청은 질문 목록과 공개 프로필 조회만 허용한다. 소유자 프로필·기록·버전·공개
  변경은 bearer token의 소유자 ID를 서버에서 확인하고 요청 본문의 사용자 식별자를 신뢰하지 않는다.

## 보안과 개인정보 영향

- 원문 토큰과 이메일·비밀번호를 애플리케이션 로그에 기록하지 않는다.
- 로그인 오류는 `INVALID_CREDENTIALS`, 만료·폐기 세션은 `UNAUTHENTICATED`로 구분하되 계정
  존재 여부나 내부 저장 상태를 노출하지 않는다.
- 인증 만료 후 Client는 작성 중 원문을 자동 재전송하지 않고 사용자가 다시 로그인한 뒤 명시적으로
  저장하도록 한다.
- 운영 환경은 TLS를 필수로 사용한다. 내부 알파의 환경 기반 bootstrap은 정식 계정 운영 도구가
  준비되면 제거한다.

## 검토한 대안

### 공개 이메일 가입

검증 인원을 빠르게 늘릴 수 있지만 이메일 확인, 비밀번호 재설정, 남용 방지와 계정 삭제 정책을
동시에 확정해야 하므로 내부 알파 범위를 넘는다.

### JWT access token

서버 조회 없이 검증할 수 있지만 즉시 폐기와 기기별 세션 관리가 복잡해진다. 현재 규모에서는
해시된 불투명 세션이 공개 범위 변경과 접근 회수를 더 단순하고 명확하게 강제한다.

## 후속 작업

- 정식 가입·이메일 확인·비밀번호 재설정·MFA와 전체 기기 로그아웃 정책을 별도 ADR로 결정한다.
- 운영자 계정 발급 도구가 준비되면 bootstrap 설정을 제거한다.
- 정식 Web Client를 제공할 때 쿠키 기반 세션과 CSRF 보호를 다시 검토한다.

## 되돌리기

Client는 토큰 저장소와 `AuthApi` 경계에만 의존하고, 서버의 소유권 검증은 인증 방식과 분리한다.
향후 OIDC 또는 다른 세션 방식으로 전환하더라도 사용자·기록·공개 권한 모델은 유지한다.
